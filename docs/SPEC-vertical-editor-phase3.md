# SPEC-vertical-editor-phase3: 快適性（コメントUI・入力補助・画像・設定フォーム・入稿ビルド）

作成日: 2026-07-16
ステータス: **確定**（2026-07-16 インタビュー済み。§13 参照）
親SPEC: [SPEC-vertical-editor.md](SPEC-vertical-editor.md) §5.1 Phase 3

## 1. 目的・完了条件

親SPEC §5.1 Phase 3「快適性」の詳細仕様。Phase 2 で成立した2ペインWebエディタに、執筆を快適にする機能群を足し、**親SPEC §2 の5要件＋挿絵（§4.6）をすべてUI上で満たす**。

**完了条件（親SPEC §10-3）**:

1. コメント `<!-- -->` がエディタで色付き表示・一覧からジャンプでき、プレビューとPDFのどちらにも一切現れない
2. ルビ入力補助で記法を知らなくてもルビが振れる
3. 字数カウントがコメント・記法を除外して本文のみを数える
4. 画像をドラッグ&ドロップすると `images/` へのコミット＋挿入記法の追記が行われ、プレビューに反映される
5. エディタUIから入稿ビルドを起動し、ReleasesのPDFに到達できる

## 2. 前提と再利用資産

Phase 2 完了（2026-07-16・PR #12・本番反映済み）により以下が揃っている:

- **エディタ本体**: `app/(app)/projects/[id]/editor/`・`components/editor/`（CodeMirror 6 入力ペイン・Vivliostyle プレビューペイン・保存＝コミット・IndexedDB待避・競合マージ・全体プレビュー・新規章作成）
- **HTMLコメントの色付き表示**は Phase 2 で実装済み（本Phaseは一覧・ジャンプ・挿入補助を足す）
- **Server Actions**: `lib/actions/editor.ts`（`loadEditorContext` による認証＋所有確認＋PAT解決・レート制限の型）
- **GitHubクライアント**: `lib/git/github.ts`（`getFileContent` / `putFileContent` / `createFileContent` / `getManuscriptTree` / `getDefaultBranch`）。タグ作成・Release取得は本Phaseで追加（§6）
- **book.config.js の正規表現抽出**: `lib/editor/book-config.ts`（`extractEntryPaths` / `extractThemePath` / `joinRepoPath`）
- **原稿リポジトリ規約**: Actions 入稿ビルドは `v*-nyuko` タグ push がトリガー、成果物は同タグの Release に添付（`docs/templates/manuscript-repo/`・<poc-repo> で実走済み）
- **テーマの記法クラス**: 傍点 `.tenten`・縦中横 `.tcy`（`themes/nekonote-parts.css`）

## 3. コメント一覧UI

- 入力ペインのサイドバー（章一覧と切替 or 併設）に、編集中の章の `<!-- -->` コメントを**出現順に一覧表示**する
- クリックで該当行へジャンプ（CodeMirror の `EditorView.scrollIntoView`＋一時ハイライト）
- 一覧は編集内容から都度パース（デバウンス）。複数行コメントは1件として先頭行を要約表示
- **コメント挿入ショートカット**: `Cmd/Ctrl+/` で選択範囲を `<!-- -->` で包む／未選択ならカーソル位置に空コメントを挿入してカーソルを中に置く（行コメント＝没文の保留にも使える。親SPEC §4.5）
- **削除ボタン**（Issue #19・2026-07-30 追記）: 各コメント項目に削除ボタンを置き、該当コメントを本文から除去する。コメントだけの行は行ごと（末尾の改行含む）削除して空行を残さない。通常の編集として扱うため `Cmd/Ctrl+Z` で取り消せ、保存＝コミットは既存の保存フローのまま人間が行う。一覧はデバウンス更新で位置がずれ得るため、削除前に該当範囲が今もコメント本体であることを検証し、ずれていたら削除せず一覧を更新して案内する。phase4 で書き戻したレビューコメントの消化（削除）もこの操作を使う

## 4. ルビ・記法入力補助

「記法を知らなくても使える」ためのUI。挿入結果はすべて素のVFMテキストであり、プレビュー・入稿への影響はテーマCSSが既定どおり処理する。

- **ルビ**: テキスト選択 → ツールバーボタンまたは `Cmd/Ctrl+R` → ポップオーバーで読みを入力 → `{選択文字|読み}` に置換。未選択時はダイアログで親文字＋読みを両方入力
- **傍点**: 選択 → ボタン → `.tenten` クラス付与の記法に置換（VFMのインライン属性記法が通らない場合は `<span class="tenten">…</span>` を挿入。実装時にプレビュー・入稿PDF両方で検証して片方に確定する）
- **縦中横**: 選択（2〜3桁の半角英数を想定）→ ボタン → `.tcy` 同上
- ツールバーは入力ペイン上部に小さく置く（ルビ・傍点・縦中横・コメント・画像の5ボタン＋字数表示）

## 5. 字数カウント・ページ数見積り

- **字数**: 本文のみを数える。除外対象＝HTMLコメント・フロントマター・見出し記号 `#`・ルビの読み部分（`{漢字|かんじ}` は「漢字」のみ数える）・クラス指定記法・画像記法・空白改行
- 表示はツールバー右端（`12,345字`）。入力のデバウンスで更新
- **ページ数見積り**: `字数 ÷ (行数×字/行)`（テーマの版面: 文庫A6=16行×40字、B6=17行×44字）の概算値を「約◯ページ」で併記。部分プレビュー完了時は Vivliostyle が組んだ**実ページ数**を優先表示する
- 実装は `lib/editor/word-count.ts` の純関数（テスト可能な形で切り出し）

## 6. 画像アップロード・挿入補助

- **入口は2つ**: 入力ペインへのドラッグ&ドロップ／ツールバーの画像ボタン（ファイル選択）
- フロー: 検証 → `images/{ファイル名}` へ**即コミット**（`createFileContent`）→ エディタのカーソル位置に挿入記法を追記 → プレビューはデバウンスで反映（画像は既存の認証プロキシ `/api/editor/asset` 経由）
- 挿入記法は種別を選ぶ: 本文中カット `![キャプション](../images/xxx.png){.illust-inline}` ／全面挿絵 `{.illust-full}`（ドロップ時にポップオーバーで選択・既定は本文中カット）
- **検証（クライアント＋サーバー両方）**:
  - 拡張子allowlist: png / jpg / jpeg / webp / gif（画像プロキシと同一）
  - サイズ上限: 10MB（超過は日本語エラー）
  - ファイル名はサニタイズ（英数字・`-`・`_`・`.` のみに正規化。衝突時は `-2` 連番）
- 解像度・カラーの入稿検査は既存の Actions 内検査（`check-images.mjs`）の責務のまま（エディタでは行わない）
- Server Action: `uploadImage(projectId, fileName, base64Content)` — `loadEditorContext`＋レート制限＋パス検証（`images/` 配下固定）。**security-reviewer 対象**（§10）

## 7. 設定フォーム（書誌・entry・組み設定・奥付）

親SPEC §8 論点7「Phase 3 でフォーム化」の実装（論点Aで**組み設定・テーマ変数まで**に確定）。**設定ファイルの実体（JS/CSS/md）が正**であり、フォームは既存ファイルの該当箇所だけを正規表現ベースの文字列置換で書き換える（実行もASTパースもしない——読み取り側 `extractEntryPaths` と対称の方式）。壊れた書き換えを防ぐため、**置換後に抽出関数を再実行して期待どおりの値が読めることを検証してからコミット**する。対応できない構造は該当セクションを読み取り専用にし、「VS Code等で直接編集してください」と案内する（フェイルソフト）。

対象は5区画。それぞれ独立に保存＝コミット（`putFileContent`・楽観ロック・メッセージ自動生成・コミット前に差分プレビュー表示）:

1. **書誌情報**（`book.config.js` の `title` / `author`）: テキストフィールド。文字列リテラルの値部分のみ置換
2. **章順（entry管理）**: entry 配列をリスト表示し、並べ替え（上下ボタン）・追加（entry未登録章の取り込み）・除外。`{ rel: 'contents' }`（目次差し込み位置）等の非文字列要素は位置を保って表示のみ（並べ替え対象・削除不可はUIで区別）。**新規章作成時に entry へ自動追記する**（Phase 2 の積み残し）。`book.config.b6.js` は `book.config.js` を spread 継承するテンプレート構造のため**同期不要**（継承していないリポジトリでも book.config.js のみを正として扱う）
3. **組み設定（テーマ変数）**: `book.config.js` の `theme` が指すCSSの `:root` 変数——行数 `--vs-theme--num-of-line`・字詰め `--vs-theme--num-of-character`・行送り `--vs-line-height`・フォントサイズ `--vs-font-size-on-print`——を数値フィールドで編集。`book.config.b6.js` があれば判型タブ（A6/B6）で両テーマを切替編集できる（同一の変数構造・ファイルパスだけ差し替え）。変数が見つからないテーマは読み取り専用
4. **ノンブル・柱**（Issue #237）: 組み設定と同じテーマCSSの `:root` 変数を編集する。
   ノンブル（`counter(page)`）と柱（章タイトル＝`env(doc-title)`）それぞれの位置を
   「出さない／天・小口／天・中央／地・小口／地・中央」から選ぶ。
   小口（外側）の左右は `@page :left` / `:right` で自動的に入れ替わるため、偶奇の出し分けは設定項目にしない。
   同じ位置を選んだ場合は `counter(page) '　' env(doc-title)` のように連結する。
   - 実体は4つのスロット変数 `--nekonote--slot-{top,bottom}-{outer,center}`。
     これを参照する `@page` ルールは `themes/nekonote-parts.css` に置き、**値だけ**を判型テーマの `:root` が持つ
   - マージンボックス内では文字が版面側の端に寄るため、ノンブル・柱と本文の間隔は設定項目にしない。
     広げたい場合は組み設定の字詰めを減らして天地マージンを広げる（間隔の調整可能化は別Issue）
   - スロットは `:left`/`:right` 共通のため、**柱は左右どちらのページにも出る**
     （theme-bunko 既定の「左ページのみ柱」からの変更。左右で出し分ける選択肢は持たない）
   - 書き込む値はアプリが選択肢から組み立てたものだけに限る（任意のCSSがテーマへ入らないようにする）。
     読み取り時に組み立て可能な値として解釈できなければ、その区画は読み取り専用にする（手書きカスタムの尊重）
   - 書名（`env(pub-title)`）は選択肢に含めない。プレビューは単一HTMLで出版物マニフェストを持たないため
     空になり、入稿PDFとプレビューがズレるため
5. **奥付**: テンプレート構造（フロントマター `class: colophon`＋`<dl>` の項目・発行日行）が検出できた場合のみ、発行日・著者・発行・連絡先・印刷のフィールドを提供。検出できなければ該当章へのジャンプリンクのみ（奥付は章ファイルなのでエディタで直接編集できる）

- 組み設定の変更コミット後はテーマCSSを再取得してプレビューへ反映する（`resolveThemeAssets` の再実行）
- 設定フォームの導線はエディタヘッダーの「設定」ボタン（ダイアログ or 専用パネル）
- 柱は `env(doc-title)`＝各章HTMLの `<title>` を参照する。プレビューHTMLの `<title>` も
  入稿ビルド（VFM）と同じ規則——フロントマターの `title:`、なければ先頭の H1——で入れる（Issue #237）。
  全体プレビューは単一HTML化しているため柱は全ページ共通（先頭章の見出し）になる。UIで注記する

## 8. 入稿ビルドUI

親SPEC §8 論点6「エディタUIからも起動」の実装。中身は**タグ作成の代行**であり、ビルド自体は既存の GitHub Actions がやる。

- ヘッダーの「入稿ビルド」ボタン → ダイアログ:
  1. 既存の `v*-nyuko` タグ一覧から次のタグ名を提案（例: `v0.3-nyuko`）。編集可（形式は `v*-nyuko` に検証）
  2. 対象はデフォルトブランチの最新コミット（未保存の編集がある場合は警告）
  3. 実行 → Git Refs API でタグ作成（**Contents権限で可能・PATのスコープ変更不要**）→ Actions が起動
- **完了検知は Release のポーリング**: タグ作成後、同タグの Release と PDF アセットの出現をポーリング（30秒間隔・最長15分）。取得は Releases API（Contents 権限で読める）。完了したら PDF へのダウンロードリンクを表示
  - Actions の実行ステータスAPIは使わない（fine-grained PAT に `actions: read` の追加が必要になり、スコープ拡大を避ける）。失敗時はタイムアウトとして「GitHub の Actions ページを確認してください」＋リンクを案内
- タグ直 push も引き続き有効（親SPEC §8 論点6）
- Server Actions: `createBuildTag` / `getBuildStatus`（`loadEditorContext`＋レート制限。タグ作成は書き込み経路として **security-reviewer 対象**）

## 9. データ・セキュリティ

- **DBスキーマ変更なし**。設定・画像・タグの実体はすべてGitHub（親SPEC §6）
- 新規の書き込み経路が3つ増える。いずれも `loadEditorContext`（認証＋所有確認＋PAT）＋`enforceRateLimit`＋パス検証を通し、**security-reviewer の通過を省略しない**（CLAUDE.md・親SPEC §9）:
  1. 画像コミット（`images/` 配下固定・拡張子allowlist・サイズ上限）
  2. 設定ファイルの書き換え（対象は `book.config.js`・`book.config.b6.js`・theme が指す `themes/*.css`・奥付章に固定。置換後の構造検証つき）
  3. タグ作成（`v*-nyuko` 形式に検証・デフォルトブランチのHEADのみ対象）
- PATはserver-onlyのまま。クライアントに増えるのは画像のアップロード内容と Release のPDFダウンロードURLのみ（URLはprivateリポジトリのアセットのため、ブラウザ直リンクでは開けない——サーバー経由で取得してリダイレクト or プロキシする。実装時に確認して確定）

## 11. スコープ外（Phase 4以降・積み残し）

- **スマホの入力/プレビュータブ切替**（論点Dで不採用。Phase 2 の「崩れない表示」のまま。必要になったら着手）
- ネコノテ連携（エディタ⇄レビューの相互リンク・コメント書き戻し）— Phase 4・別SPEC
- ブランチ切替・作成・PR連携（デフォルトブランチのみのまま）
- テーマCSSの自由編集（フォーム対象は §7-3 の4変数のみ）・判型の新規追加
- 縦中横・割注などの高度な組版指定の網羅的UI化（本Phaseはルビ・傍点・縦中横の3つまで）
- 画像のリサイズ・圧縮・Git LFS 移行（太ったら親SPEC §8 論点8どおり移行検討）
- Actions 実行ステータスの詳細表示（PATスコープ拡大を伴うため。完了検知はReleaseポーリングで代替）

## 13. E2E検証手順

1. 章を開く → ツールバーに字数（本文のみ）＋「約◯ページ」が出る。コメント・フロントマター・ルビ読みを足しても字数が変わらないことを確認
2. コメント一覧に `<!-- -->` が出現順に並び、クリックで該当行へジャンプ。`Cmd+/` で選択範囲がコメント化される。プレビュー・（既存タグの）入稿PDFにコメントが現れない
3. テキスト選択 → ルビボタン → 読み入力 → `{選択|読み}` に置換され、プレビューでルビが組まれる。傍点・縦中横も同様
4. 画像をD&D → 種別選択 → `images/` へのコミットがGitHubに存在し、カーソル位置に記法が入り、プレビューに画像が出る。11MB のファイル・`.svg` は日本語エラーで拒否される
5. 設定フォームで著者名を変更＋entryを並べ替え → 差分プレビュー → コミット → 章一覧の順序が変わり、`book.config.js` にコミットが存在する。新規章作成で entry に自動追記される。組み設定で行数を変更 → コミット → プレビューの版面が変わる。奥付フォームで発行者を変更 → `99-okuzuke.md` に反映される
6. 「入稿ビルド」→ タグ提案を確認して実行 → Actions が起動し、完了後にUIへPDFリンクが出る → PDFを開ける
7. 回帰: Phase 2 の保存・待避・競合マージ・全体プレビュー、ネコノテ既存機能（校正・進捗）が従来どおり動く
