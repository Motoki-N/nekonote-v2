# SPEC-beat-board: ビートボード（4部構成・シーンカード・構成/シーンレビュー）

作成日: 2026-07-13（インタビュー駆動で策定）
ステータス: **確定**（2026-07-13 レビュー済み）

## 1. 目的

4部構成・5転換点にもとづく付箋ボード方式の構成管理（要求仕様 §3.3「構成・設計支援機能」）を実装する。シーンカードのD&D配置・転換点アンカー・感情の起伏の可視化と、担当編集AIによる構成レビュー・シーンレビュー（Sprint 2 のレビュー基盤を再利用）を提供する。

前提（決定済み・変更しない）:

- UIモデル = カンバン型構造化ボード。4パート（設定・反応・攻撃・解決）を固定レーンとする
- 実装ライブラリ = dnd-kit（タッチ・アクセシビリティ対応）
- `scenes` テーブルはコアスキーマ（20260712000002）で定義済み。**今回マイグレーションは不要**
- レビュープロファイル「構成レビュー」「シーンレビュー」はシード済み（担当編集・固定UUIDは `lib/ai/personas.ts`）

## 2. 決定事項（インタビュー結果・2巡）

| 論点 | 決定 |
|---|---|
| アンカー表現 | **ハイブリッド方式**。シーンカードに転換点マークを付ける（scenes.anchor）＋マーク付きシーンはボード上で定位置に自動整列 |
| 整列規則 | **境界3点のみ固定**。PP1=設定レーン末尾、ミッドポイント=反応レーン末尾、PP2=攻撃レーン末尾に固定表示（ドラッグ並び替え不可）。ピンチポイント1・2はバッジ表示のみでレーン内自由 |
| カード編集UI | **ダイアログ＋プレーンtextarea**。タイトル・本文（4観点はplaceholderで提示）・感情の起点→終点・パート・アンカーを編集。Tiptapは使わない |
| レビュー形式 | **都度フィードバック型**。承認/差し戻し判定（verdict）・「通す」ボタンなし。履歴・返答メモは企画書レビューと同じ基盤（review_sessions / review_feedbacks）を使う |
| レビュー入力 | **企画書まで含める**（紐づけノート全文は含めない）。構成レビュー=全シーン＋企画書、シーンレビュー=対象シーン＋全シーンタイトル・アンカー一覧＋企画書 |
| 感情の起伏 | **バッジ＋ボード下部の折れ線を両方今回実装**。ただしD&D難航時の縮退第一候補は折れ線（バッジのみ残す） |
| ページ配置 | **タブで別ルート**。`/projects/[id]` 直下にタブナビ（企画書 | ビートボード）、ボードは `/projects/[id]/board` の専用フル幅ページ。Sprint 4 の原稿タブも同じ列に足せる |
| カード削除 | **確認ダイアログで即削除**（物理削除）。ごみ箱は使わない（シーンカードは短文メモで再作成コストが低い） |

## 3. 画面とUX

### 3.1 タブナビ（`/projects/[id]` 共通）

- プロジェクトページ直下にタブ（企画書 | ビートボード）を追加。共通レイアウト（`app/(app)/projects/[id]/layout.tsx`）でプロジェクト情報ヘッダー＋タブを描画
- 既存の企画書ページは `/projects/[id]`（タブ=企画書）のまま。ボードは `/projects/[id]/board`

### 3.2 ビートボード（`/projects/[id]/board`）

- **デスクトップ**: 4レーン横並び（設定・反応・攻撃・解決）のフル幅レイアウト。レーンヘッダーにパート名＋パートの意味の短い説明（story-engineering 準拠）
- **スマホ**: レーンを縦積み（設定→反応→攻撃→解決）。タッチ長押しでドラッグ
- **シーンカード**: タイトル＋本文の先頭数行＋感情バッジ（起点→終点の矢印。plus/minus を色ではなくアイコン＋テーマ変数色で表現）＋アンカーバッジ（PP1等）
- **D&D**（dnd-kit: PointerSensor + TouchSensor + KeyboardSensor）:
  - レーン内並び替え・レーン間移動。ドロップ確定で楽観的UI更新→Server Action保存、失敗時はロールバック＋トースト
  - レーン間移動で `part` が更新される
- **境界アンカーの固定表示**: 各境界アンカー（PP1/ミッドポイント/PP2）は該当レーン末尾の専用スロットに表示
  - アンカー未設定のスロットは薄いプレースホルダー（例:「PP1: プロットポイント1（未設定）」）として常時表示し、「まだ決まっていない転換点」を可視化する
  - 境界アンカー付きシーンはドラッグ並び替え不可（スロットに固定）。外すには編集ダイアログでアンカーを解除する
  - 通常カードのドロップ先・「＋シーンを追加」はスロットの手前まで
- **ピンチポイント1・2**: バッジ付きの通常カードとしてレーン内で自由に動かせる
- **感情の折れ線**: ボード下部に、構成順序（order_index）に沿った emotion_start→emotion_end の遷移をSVG折れ線で表示（plus=上・minus=下の2値）。未設定シーンはスキップ。並び替え・編集に追従
- **カード追加**: 各レーン末尾（境界スロットの手前）に「＋シーンを追加」→ 空カードを作成して編集ダイアログを開く

### 3.3 カード編集ダイアログ

- タイトル（1行）
- 本文（プレーンtextarea）。placeholderで4観点を提示: シチュエーション（場所・時刻）／起きること／感情の変化／葛藤
- 感情: 起点・終点それぞれ「プラス / マイナス / 未設定」のトグル
- パート選択（4択）。**境界アンカーが付いた状態でパートを変更するとアンカーは自動解除**（ダイアログ内に注意書きを表示）
- アンカー選択: 現在のパートに応じた選択肢のみ表示（設定=PP1、反応=ピンチ1/ミッドポイント、攻撃=ピンチ2/PP2、解決=なし）＋「なし」
  - **1転換点1シーン**: すでに他のシーンに付いているアンカーを選んだ場合は付け替え（元のシーンからは自動で外れる。ダイアログにその旨を表示）
- 保存ボタンで確定（ダイアログのため自動保存はしない）。削除ボタン→確認ダイアログ→物理削除
- カードメニュー（またはダイアログ内）から「シーンレビューを受ける」→ レビューパネルが対象シーンで開く

### 3.4 レビューパネル（構成レビュー / シーンレビュー）

- ボードページに企画書と同型のパネル（デスクトップ=右サイドパネル、スマホ=ボトムシート）。レビューパネルのコンポーネントは企画書のものを共通化して再利用する
- **構成レビュー**: ボードヘッダーの「構成レビューを受ける」から実行。対象=ボード全体
- **シーンレビュー**: カードから起動。対象=そのシーン
- 都度フィードバック型: フィードバック文書のストリーミング表示・履歴・返答メモは企画書と同じ。**判定バッジ・「通す」ボタンは表示しない**（verdict は保存しない）
- セッション: 対象ごと（構成=プロジェクト、シーン=各シーン）に running セッション高々1本（アプリロジック。企画書と同じ）。`target_ref` に格納する値: 構成レビュー = project id、シーンレビュー = scene id
- 2回目以降は同一セッションの過去フィードバック＋返答メモを全て渡す（「前回の指摘が直ったか」を見られる）
- シーンが削除されたら、そのシーンのレビューセッションは履歴ごと削除する（運命共同体。scenes cascade はDB定義済みだが target_ref は text 参照のため Server Action で明示削除）
- エラーは日本語メッセージをパネル内表示（既存の AppError 正規化を踏襲）。生成中の多重実行抑止・stopボタンも同様

### 3.5 レビューのプロンプトとコンテキスト

- system = 担当編集ペルソナ `description` ＋ 各プロファイルの `prompt_template`（シード済み。構成=4部構成・5転換点チェックリスト、シーン=4観点）
- user 入力:
  - **構成レビュー**: 企画書（ジャンル・ターゲット層・本文）＋全シーンを構成順に整形（パート・アンカー・タイトル・本文・感情の起点→終点）＋同一セッションの過去履歴
  - **シーンレビュー**: 企画書（同上）＋対象シーン全文＋前後の流れが分かる全シーンのタイトル・アンカー・感情の一覧（本文は対象シーンのみ）＋同一セッションの過去履歴
- 出力 = Markdown のフィードバック文書のみ（判定行なし）

## 4. データ

**マイグレーションなし**。既存スキーマの運用セマンティクスのみ確定する:

- `scenes.order_index`: プロジェクト内の通し番号（0..N-1）。カードの並びは (order_index) 昇順が正、レーン表示は part でフィルタ。D&D確定時は該当プロジェクトの全シーンを新順序で一括再採番する（シーン数は高々数十。1 Server Action = 1トランザクションで整合を保つ）
- `scenes.anchor`: 1転換点1シーンはアプリロジックで担保（付け替え時に元シーンの anchor を null に更新。DB unique 制約は追加しない）。境界アンカーのシーンは「該当レーンの order_index 上の末尾」に置く
- `scenes.part` と anchor の整合（pp1⇔setup 等）もアプリロジックで担保
- `review_sessions.target_ref`: 構成レビュー = project id、シーンレビュー = scene id。`review_feedbacks.verdict` は null のまま使わない

## 5. 実装方式

- **依存追加**: `@dnd-kit/core` `@dnd-kit/sortable`（軽量・タッチ対応）
- **API**: 既存 `POST /api/review` を拡張し、レビュー種別（proposal | structure | scene）を受け取る。認証チェック→対象（project / scene）の所有確認（RLS越し取得）→コンテキスト組み立て→ `resolveModel` → `streamText` → onEnd で feedback 保存、の流れは既存と同じ。structure / scene では verdict パースをスキップ
- **Server Actions**（`lib/actions/scenes.ts` 新設）: シーン作成・更新（アンカー付け替え・パート変更時のアンカー解除込み）・削除（レビューセッション明示削除込み）・並び替え一括保存。Zod＋AppError の既存パターン（`{ok, error}` 戻り値）
- **プロンプト組み立て**: `lib/ai/prompts.ts` に構成/シーンレビューを追加（企画書レビューと並置）
- 楽観的UI更新は React の useOptimistic か同等の手動ロールバックで実装（シンプルな方を選ぶ）
- 色はテーマ用CSS変数のみ（感情バッジ・折れ線・アンカースロット含む）
- **縮退計画**（実装計画の判断ルール準拠）: D&Dが1日詰まったらリスト形式（上下移動ボタンによる並び替え）に縮退、2次元ボードはR2へ。折れ線は縮退第一候補

## 7. スコープ外

- ごみ箱（シーンは物理削除）
- 感情の強度・数値化、折れ線の高度化（2値のプラス/マイナスのみ）
- シーンカードへのノート紐づけ・原稿ファイルとの紐づけ（後者は Sprint 4 以降）
- 4部構成以外の構成テンプレート（三幕構成など）
- 構成/シーンレビューのゲート化（verdict・「通す」ボタン）
- 担当ペルソナの実行時変更UI（Sprint 5）
- レビュー入力への紐づけノート全文の投入（企画書までにとどめる）
- 過去レビューセッションの一覧画面

## 8. E2E検証手順（完了条件）

1. **タブ導線**: `/projects/[id]` にタブが出る→ビートボードタブで `/projects/[id]/board` へ。企画書ページの既存機能が壊れていない（回帰）
2. **カードCRUD**: 各レーンで追加→編集ダイアログ（タイトル・本文・感情トグル）→保存→リロードで復元。削除→確認ダイアログ→DBから物理削除を確認
3. **D&D**: レーン内並び替え・レーン間移動（part 更新）→リロードで順序保持（order_index の再採番をDBで確認）
4. **境界アンカー**: 編集ダイアログでPP1指定→設定レーン末尾スロットに固定・ドラッグ不可→別シーンにPP1を付けると元から外れる→パート変更でアンカー自動解除。空スロットのプレースホルダー表示
5. **ピンチポイント**: バッジ表示のままレーン内でドラッグできる
6. **感情の可視化**: 起点/終点設定→カードバッジ表示→ボード下部の折れ線が構成順序・編集に追従
7. **構成レビュー**: 実行→ストリーミング表示→シーン構成と企画書の両方を踏まえた指摘→返答メモ→再レビューで前回への言及。判定バッジ・「通す」ボタンが出ないこと
8. **シーンレビュー**: カードから起動→対象シーンの4観点への指摘→シーン削除でセッションも消える
9. **モバイル**: スマホ幅（375px）で縦積み表示、タッチでのD&D（または編集ダイアログのパート変更による移動）で 2〜8 相当の操作が成立
10. **キー未設定エラー**: ANTHROPIC_API_KEY を外すと日本語エラーがパネルに出て落ちない
11. **RLS回帰**: anon キーの REST SELECT で scenes が拒否される（既存ポリシーの確認のみ）

※ マイグレーションはないが、`/api/review` の対象拡張（scene / project の所有確認）は **security-reviewer ゲート**の対象とする。
