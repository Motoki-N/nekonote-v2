## 2. 各ステップ計画

### Step 0: 現状の凍結（半日）

**目的**: リファクタリング前の基準線を確定する。

- [ ] `docs/TESTING.md` 新規作成: 全機能の回帰テストチェックリスト。各 SPEC の E2E 節と manual.md の機能一覧から集約し、以後の各段階で使い回す
- [ ] タグ付け: `v0.2.0-rc`（本リポジトリ初のタグ。main の HEAD へ）
- [ ] TESTING.md に沿って回帰テストを一周、グリーン確認。NG 項目は GitHub Issue に起票し `/fix-issue` フローで個別修正

**注意**: 本番にはドッグフーディングの実データがある。回帰テストは検証専用プロジェクトを作成して実施し、終了時に削除して原状復帰する（破壊系操作は実データに触れない）。

**指示例**:
> 各SPECのE2E節とmanual.mdを素材に、全機能の回帰テストチェックリスト docs/TESTING.md を作成。作成後、チェックリストに従い回帰テストを一周し、結果をチェックリスト形式で報告。検証は専用プロジェクトを作って実施し終了時に削除。NG項目はIssue起票して別セッションで修正。

### Step 1: コードレビュー＆リファクタリング

**目的**: 保守性向上。レビューと修正を分離し、勝手な大改造を防ぐ。

- [ ] レビュー（修正なし・分類リスト化のみ）。前回レビュー `docs/code-review-20260714.md` 以降の差分観点を含める
- [ ] レビュー結果から対象を取捨選択し SPEC 化（人間が選ぶ）
- [ ] 段階分割で実施（構造整理 → 重複統合 → 型・エラーハンドリング → パフォーマンス）
- [ ] 各段階後に TESTING.md で回帰テスト

**ゲート**: 3ファイル以上にまたがるリファクタリングは着手前に人間へ設計確認（CLAUDE.md 既定）。認証・RLS・秘密情報に触れる場合は security-reviewer 必須。

**指示例（レビュー）**:
> 保守性向上を目的にコードベース全体をレビュー。修正はせず、問題点を「重複コード / 命名不統一 / 責務違反 / 型の緩さ / 未使用コード」に分類してリスト化し、影響範囲と優先度を付けて報告。docs/code-review-20260714.md の前回指摘の消化状況も併記。

### Step 2: セキュリティレビュー＋依存パッケージ更新

**目的**: コード確定後の状態で念入りに検証。公開化（Step P)の前提ゲートを兼ねる。

- [ ] 全テーブルの RLS ポリシー網羅確認（マイグレーション28本）
- [ ] API ルートの認証・認可チェック
- [ ] PAT・API キーがクライアントバンドル / ログに漏れる経路の確認（`lib/git/credentials.ts` の `GitCredentialProvider` 経由の徹底）
- [ ] 入力バリデーション
- [ ] `npm audit`（現状 20件: high 10 / moderate 10、主に vivliostyle 系依存の valibot）＋依存パッケージ更新
- [ ] 修正後に TESTING.md で回帰テスト

**参考**: 前回監査 `docs/security-audit-20260714.md`。今回は「前回以降の差分＋全体再点検」として実施し、結果は日付つきで docs/ に残す。security-reviewer の通過を完了条件とする。

**指示例**:
> セキュリティ観点で全体レビュー。観点: (1)全テーブルのRLSポリシー網羅性 (2)APIルートの認証・認可 (3)PAT・APIキーのクライアント露出経路 (4)入力バリデーション (5)npm audit結果。docs/security-audit-20260714.md 以降の差分を明示。修正提案は重大度順にリスト化、修正は承認後に実施。

### Step P: リポジトリ公開化【指示書外・今回追加】

**目的**: プライベートリポジトリを public へ切り替える。準備作業は完了済みで、残りは切り替えと最終確認のみ。

- [ ] 前提条件: Step 2（セキュリティレビュー）完了
- [ ] 公開前最終チェック: git 全履歴と docs（特に dev-log.md・incident-log.md）を「公開すべきでない情報」（CLAUDE.md の規約: 秘密情報の実値・実メールアドレス・私的リポジトリ名・未公開作品の実タイトル・インフラ識別子）の観点で最終走査
- [ ] GitHub での可視性切り替え: **ユーザー自身が操作**（外部サービスのダッシュボード操作はユーザー実施の流儀に従う）
