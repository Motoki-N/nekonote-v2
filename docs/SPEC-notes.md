# SPEC-notes: 構想支援（手帳→プロットモデル）

作成日: 2026-07-12（インタビュー駆動で策定）
ステータス: **ドラフト**（ユーザーレビュー待ち）

## 1. 目的

第一期の問題「構想メモのフォーマットが硬く自由度が低い。結局Notionに流出」を解消する。
紙の手帳にアイデアを書き留め、後からプロットに落とし込んでいく体験を再現する（草稿→浄書モデル）。
設計思想は `draft-to-clean-model` スキルが正。**構造はテキストとして持ち、システムが管理する構造を最小にする**。

## 2. 決定事項（インタビュー結果）

| 論点 | 決定 |
|---|---|
| エディタ方式 | WYSIWYG（Tiptap）。Notionに近い書き心地を優先 |
| 保存形式 | **Markdown**（tiptap-markdown で往復変換）。`notes.content` はMarkdownという設計を維持し、対応記法を往復安全な範囲に限定する |
| 保存モデル | 自動保存（入力停止後数秒のデバウンス＋離脱時保存）。保存失敗時は localStorage へドラフト退避（SPEC-auth §6 が要件の正） |
| タグUX | インライン作成。ノート画面のタグ入力欄で既存候補から選択 or その場で新規作成（種類を選んで） |
| テンプレート管理 | **DBテーブル（`templates`）**。ハイブリッド所有モデル（標準同梱行 user_id null＋ユーザー作成行、personas と同型） |
| テンプレート挿入 | カーソル位置に雛形を挿入＋対応する category タグを自動付与 |
| AI掘り下げ支援 | **別SPECに分離**（Vercel AI SDK導入・ai_model_settings とセットで Sprint 1 後半にインタビュー） |
| 削除 | 即時削除＋確認ダイアログ（ごみ箱・ソフトデリートは作らない） |
| 端末間競合 | last-write-wins（後勝ち）。ソロ利用のため楽観ロックは作らない（既知の制約として記録） |

## 3. 画面とUX

### 3.1 ノート一覧（`/notes`）

- 新規作成ボタン: **1クリックで空ノートを作成してエディタへ遷移**（作成の手数最小）
- 各ノートの表示: タイトル（空なら「無題」）・本文冒頭の抜粋・タグ・更新日時
- 並び順: 更新日時の降順
- 絞り込み: タグチップで絞り込み（category / working_title を区別して表示）。複数タグはAND
- 検索: タイトル＋本文の部分一致（ILIKE）。MVPでは全文検索インデックスを張らない

### 3.2 ノートエディタ（`/notes/[id]`）

- タイトル入力欄＋Tiptap本文エディタ＋タグ入力欄＋テンプレート挿入メニュー
- **対応記法（往復安全な範囲に限定）**: 見出し（H1〜H3）・箇条書き/番号リスト・太字/斜体・リンク・引用・区切り線
  - 表・画像・コードブロックはスコープ外（往復変換の欠落リスクを避ける）
- 保存状態インジケータ（保存中… / 保存済み / オフライン退避中）を常時表示
- スマホ幅で全操作（入力・タグ付け・テンプレ挿入）が成立すること

### 3.3 自動保存とドラフト退避（SPEC-auth §6 の実装先）

1. 入力停止後数秒のデバウンスで自動保存（＋ページ離脱時にも保存）
2. 保存APIが失敗（401・ネットワーク断）した場合、localStorage にノートID単位でドラフト退避
3. 復帰時に localStorage のドラフトとサーバー値を比較し、ドラフトが新しければ復元して保存を提案
4. 保存成功時にドラフトを削除

### 3.4 タグ

- タグ入力欄: 既存タグをインクリメンタル候補表示。一致がなければ「新規作成（category / working_title を選択）」
- working_title（仮タイトル）は作品の卵の名前。一覧の絞り込みで「同じ作品候補に属するノート群」を束ねる
- タグの改名・削除UIはMVPでは作らない（削除は note_tags が cascade で外れるだけ。必要になったら一覧側に追加）

### 3.5 テンプレート挿入（プロットに落とし込む）

- エディタの挿入メニューからテンプレートを選択 → **カーソル位置に雛形Markdownを挿入**
- 挿入と同時に、テンプレートに紐づく category タグをノートへ自動付与（そのユーザーのタグを get-or-create）
- 挿入後もノートはただのMarkdown。追記・逸脱が可能（構造の強制はしない）
- 標準同梱テンプレート（初期セット）: コンセプト / キャラクター / テーマ / 世界観。雛形本文は story-engineering スキル準拠でシード時に確定

## 4. データ

### 4.1 既存スキーマの利用

`notes` / `tags` / `note_tags`（20260712000002_core_schema.sql 定義済み）をそのまま使う。スキーマ変更なし。
バリデーションは `lib/schemas/notes.ts`（定義済み）を使用。

### 4.2 追加テーブル: `templates`（要マイグレーション）

personas と同型のハイブリッド所有モデル。**作成は次セッションでプランモード承認の上行う**。

```
templates:
  id uuid PK
  user_id uuid null可（null = 標準同梱）
  name text not null            … コンセプト、キャラクター、など
  content text not null         … Markdown雛形本文
  tag_name text null可          … 挿入時に自動付与する category タグ名（notes 側で get-or-create）
  is_default boolean            … personas と同じ CHECK 制約・RLSポリシー構成
  created_at / updated_at
```

- 標準テンプレの雛形本文はこのマイグレーション（または直後のシード）で投入する
- RLS: SELECT は「標準 or 自分の行」、INSERT/UPDATE/DELETE は自分の行のみ（personas のポリシーを踏襲）

## 5. 実装方式

- データ取得: Server Component で一覧・初期値を取得
- 変更系: Server Actions（Zodでバリデーション → Supabase）。エラーは `AppError`＋共通ハンドラー経由
- エディタ: `@tiptap/react`＋`@tiptap/starter-kit`（不要な拡張は無効化）＋Markdown変換拡張。**色はテーマ用CSS変数のみ使用**（Tiptapのデフォルトスタイルを持ち込まない）
- 型: `Database` 型（lib/database.types.ts）。templates 追加後に `npm run db:types` で再生成

## 6. 対象ファイル

| ファイル | 役割 |
|---|---|
| `supabase/migrations/XXXX_templates.sql` | templates テーブル＋RLS＋標準テンプレシード（プランモード承認後） |

| `lib/actions/notes.ts` 等 | ノート/タグ/テンプレ挿入の Server Actions |
| `lib/database.types.ts` | templates 追加後に再生成 |

## 7. スコープ外

- **AI掘り下げ支援**（Vercel AI SDK導入・ai_model_settings と合わせて別SPEC）
- テンプレートの作成・編集・複製UI（スキーマは対応済みにする。UIは設定画面＝Sprint 5）
- 表・画像・コードブロック等の高度な記法、ファイル添付
- 全文検索の高度化（pg_trgm / FTS。ILIKEで遅くなったら検討）
- ノートのバージョン履歴・ごみ箱・エクスポート
- リアルタイム同期・共同編集（端末間競合は last-write-wins）
- ノートとプロジェクトの紐づけ（企画書経由の紐づけは SPEC-proposal 側で扱う）

## 8. E2E検証手順（Sprint 1 完了条件）

1. **作成**: 一覧から1クリックで空ノートが作られエディタへ遷移。本文入力→「保存済み」表示→一覧に反映される
2. **Markdown往復**: 見出し・リスト・太字/斜体・リンク・引用・区切り線を含むノートを保存→リロード→表示の欠落・崩れがない。DB上の `content` がMarkdownテキストであること
3. **タグ（インライン作成）**: エディタから category / working_title 各1つを新規作成して付与できる
4. **絞り込み**: 一覧で working_title タグを選ぶと、同じ作品候補のノート群だけが表示される。複数タグでANDが効く
5. **検索**: タイトル・本文の部分一致でヒットする
6. **テンプレ挿入**: カーソル位置に雛形が挿入され、対応する category タグが自動付与される。挿入後に自由編集できる
7. **ドラフト退避**（SPEC-auth §6 持ち越し分）: オフライン状態で編集→退避表示→オンライン復帰・再ログイン後に復元提案→保存できる
8. **削除**: 確認ダイアログ→削除→一覧から消える。タグ自体は残る（note_tags のみ外れる）
9. **モバイル**: スマホ幅で 1〜6 の操作が成立する
10. **RLS**: 別ユーザーのノート・タグ・テンプレ（ユーザー作成分）が一切見えない。標準テンプレは見える

※ 実運用移行（Notionからのネタメモ引っ越し）は完了条件「Notionの代わりにネコノテでネタメモが取れる」の実地確認を兼ねる。
