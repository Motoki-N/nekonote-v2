# SPEC-manuscript-history: コミット履歴表示・差分（diff）ビュー（原稿タブ）

作成日: 2026-08-09（Issue #31 のインタビュー駆動で策定）
ステータス: **確定**（2026-08-09 インタビュー済み）
親SPEC: SPEC-proofreading（§7スコープ外項目のうち「コミット履歴表示・差分（diff）ビュー」を切り出し。「ブランチ選択」は対象外のまま）

## 1. 目的

校正コミット・保留のコメント書き戻し・エディタ保存の結果を、GitHubへ往復せずアプリ内で確認できるようにする（Issue #31）。
原稿タブで開いているファイルのコミット履歴と、各コミットでの変更内容（diff）を表示する。

## 2. 決定事項（インタビュー結果・2026-08-09）

| 論点 | 決定 |
|---|---|
| 履歴の表示単位 | **開いているファイル単位**（`GET /commits?path=`）。モノレポで他作品のコミットが混ざらない。`last_reviewed_commit`（ファイル単位SHA）の既存思想と一致 |
| diffの範囲 | **各コミットの変更内容のみ**（親との差分）。履歴のコミットを選ぶと「そのコミットでの変更」を表示。任意の2コミット間比較（Compare API）はやらない |
| ブランチ | **デフォルトブランチ固定**。原稿タブの現状セマンティクス（校正・コミット書き戻しもデフォルトブランチ）を踏襲。エディタ側のブランチ選択（SPEC-vertical-editor-phase5）とは独立 |
| diffの表示形式 | **行単位＋行内文字ハイライト**。GitHubのpatch（行単位）を土台に、対応する削除行/追加行のペアで文字単位の差分をクライアント側で計算して強調。小説は段落=1行になりがちで、行単位だけでは一字修正が見つけられないため |

インタビューで聞かずに設計原則で決めた点（レビューで確認）:

- **件数は最新30件固定**（`per_page=30`・ページングなし）。校正結果の確認という用途には直近で十分。必要になったら「さらに表示」を検討
- **patchの取得は `GET /repos/{repo}/commits/{sha}`** の `files[]` からそのファイルのエントリを抽出（リネームは `previous_filename` も突き合わせ）。patch が無い場合（差分過大・バイナリ扱い）は「差分を表示できません」の日本語表示
- **行内文字ハイライトは共通接頭辞・接尾辞のトリム方式**。hunk内で連続する削除行の並びと追加行の並びを順に対応付け、各ペアの共通接頭辞・接尾辞を除いた中間部を強調する。本格的なLCS/diffライブラリは入れない（設計原則: 最もシンプルな方法）
- **UIは既存パネルと同じレイアウト言語**（lg以上=右サイドパネル、lg未満=ボトムシート）。校正・講評パネルと排他表示
- **色はテーマ用CSS変数のみ**: 削除行=`destructive` 系の透過、追加行=`primary` 系の透過（ハードコード禁止の規約に従う）
- **DBスキーマ変更なし・書き込みなし**。GitHub API は読み取りのみ（Contents: Read の範囲。PATの権限追加不要）
- **Server Action は既存パターン**（Zod検証・RLS越し所有確認・`{ok, error}` 戻り値）。コミットSHAは40桁hexをZodで検証

## 3. 画面とUX（原稿タブ）

- 原稿ビューのヘッダーに「**履歴**」ボタンを追加（ファイルを開いているときのみ）
- 履歴パネル:
  - 開くとそのファイルのコミット一覧を取得して表示: コミットメッセージ（1行目）・日時（JST）・SHA短縮7桁
  - コミットを選ぶとそのコミットでの変更内容（そのファイルのdiff）を展開表示。再クリックで閉じる
  - diff表示: 削除行/追加行を色分け（行単位）＋対応ペアの変更部分を文字単位で強調。コンテキスト行はそのまま
  - patch が取得できないコミット（差分過大等）は「差分を表示できません」
  - 取得エラー（PAT失効・不達）は日本語メッセージをパネル内表示（既存の作法）
- 校正パネル・講評パネルとの排他表示（同時に1パネルのみ）
- モバイル（375px）: ボトムシートで履歴一覧→diff展開が成立すること

## 4. API・データフロー

新規ルートは作らない。Server Action 2本を追加する:

1. `getManuscriptHistory(manuscriptLinkId)`:
   - 認証・RLS越し所有確認（manuscript_links → projects.repo）・PAT取得は既存作法
   - `GET /repos/{repo}/commits?path={filePath}&per_page=30` → `{ sha, message, date }[]` を返す
2. `getManuscriptCommitDiff(manuscriptLinkId, commitSha)`:
   - commitSha は40桁hexをZod検証
   - `GET /repos/{repo}/commits/{sha}` → `files[]` から `filename === filePath`（または `previous_filename === filePath`）のエントリを抽出し、`patch`（無ければ null）を返す
- diffのパース（hunk分割・行分類）と文字ハイライト計算はクライアント側で行う

## 6. スコープ外

- 任意の2コミット間比較（Compare API）
- ブランチ選択（原稿タブはデフォルトブランチ固定のまま）
- base_path 配下全体（作品全体）の履歴
- ページング（最新30件のみ）・コミット詳細ページ・GitHubへのリンク以外の遷移
- 縦書きエディタ側への履歴表示（原稿タブのみ）

## 7. E2E検証手順

1. **履歴表示**: ファイルを開く→「履歴」→コミット一覧（メッセージ・日時・SHA短縮）が新しい順に出る
2. **diff表示**: コミットを選ぶ→そのファイルの変更が行単位色分け＋変更部分の文字強調で表示される。段落内の一字修正が強調で見つけられる
3. **校正コミットの確認**: 校正の「確定分をコミット」実行→履歴を開くとそのコミットが先頭に出て、diffで適用内容を確認できる（Issueの動機）
4. **patchなし**: 大きすぎる差分のコミットで「差分を表示できません」が出て落ちない
5. **エラー**: PAT失効時に日本語エラーがパネル内に出る
6. **排他表示**: 履歴↔校正↔講評のパネルが同時に開かない
7. **モバイル**: 375px でボトムシート表示が成立する
8. **回帰**: 校正・講評・エディタ相互リンク等の既存機能が壊れていない

※ 変更は読み取り専用のGitHub API追加だが、PAT（秘密情報）を扱う経路に隣接するため **security-reviewer を通す**（自動フローでも省略しない）。
