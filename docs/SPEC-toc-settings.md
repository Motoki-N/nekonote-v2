# SPEC-toc-settings: 目次ページの調整・表示切り替え

作成日: 2026-10-15
ステータス: **確定**（2026-10-15 インタビュー済み・ユーザー確認済み。§10 参照）
Issue: #307
親SPEC: [SPEC-vertical-editor.md](SPEC-vertical-editor.md) §4.2（目次の自動生成）／[SPEC-vertical-editor-phase3.md](SPEC-vertical-editor-phase3.md) §7（設定フォーム）

## 1. 目的・完了条件

縦書きエディタの設定ダイアログから、入稿PDF・EPUBに入る**目次ページの有無・中身・見た目**を調整できるようにし、全体プレビューで目次ページを確認できるようにする。

**完了条件**:

1. 設定ダイアログの「目次」区画で、目次の有無・見出し文字・載せる見出しの深さ・目次から外す章・書名の表示・ページ番号の書式・リーダーを変更し、1コミットで原稿リポジトリへ反映できる
2. テンプレートの原稿で入稿ビルドすると、扉と奥付が目次に載らず、ページ番号が漢数字で組まれる（§3 の現状の問題が解消している）
3. 全体プレビューに目次ページが `entry` の位置に出て、ページ番号が入る。設定の変更がプレビューに反映される
4. 目次の設定がない既存の原稿リポジトリでも、フォームから保存すると必要な設定が追記される
5. `book.config.epub.js` があるリポジトリでは、目次の有無・見出し文字・深さが EPUB 設定にも同じコミットで反映される

## 2. 前提（Vivliostyle の目次生成の仕組み）

`@vivliostyle/cli` v11 の実装と、テンプレート原稿の試しビルドで確認した事実（2026-10-15）:

- **差し込み位置**: `entry` の `{ rel: 'contents' }` の位置に目次ページ（HTML文書）が生成される
- **`toc` があると自動で差し込まれる**: `toc` 設定があり、`entry` に `{ rel: 'contents' }` がないと、CLI が**先頭に**目次を足す。目次を「入れない」には `{ rel: 'contents' }` と `toc` の**両方**を消す必要がある
- **生成されるHTML**: `<body><h1>書名</h1><nav id="toc" role="doc-toc"><h2>目次の見出し</h2><ol>…</ol></nav></body>`。`<h1>` は `book.config.js` の `title`（書名）、`<h2>` は `toc.title`
- **項目**: `entry` の**すべての章ファイル**が1項目ずつ並ぶ（トップレベルの `<li>` は章ファイルと1対1）。項目名は章の `<title>`（フロントマター `title:` → 先頭の H1）
- **`toc.sectionDepth`**（0〜6、既定0）: 0 は章ファイル単位の項目のみ。1以上で章内の見出し（h1〜h{N}）が入れ子で載る。章に H1 が1つだけのときは、章の項目がその H1 の項目に置き換わる
- **id のない見出し**: `sectionDepth` が1以上のとき、id を持たない見出し（Markdown ではなく HTML 直書きの `<h1>` など）は**リンクのない `<span>`** になり、ページ番号も付かない
- **見た目**: theme-base（theme-bunko が読み込む）の `css/partial/toc.css` が CSS 変数で制御する。リーダー `--vs-toc--page-leader-content`（既定 `leader('.') ' '`）・ページ番号の表示 `--vs-toc--page-counter-display`・書式 `--vs-toc--page-counter-style`（既定 `decimal`）
- **EPUB**: 目次ページは EPUB のナビゲーションにも使われる。目次がない場合も CLI が非表示のナビゲーションを自動生成するため、EPUB の妥当性は保たれる

## 3. 現状の問題（テンプレート原稿のビルド結果）

- 目次ページの先頭に**書名と「目次」が二重に**出る
- **扉と奥付が目次に載る**（どちらも項目名は書名になる）
- ページ番号が `decimal` のため、縦組みで**算用数字が横倒し**になる
- いずれもアプリから直す手段がない（`book.config.js`・テーマCSSの直接編集が必要）

## 4. 設定項目と保存先

| 項目 | 選択肢 | 保存先 |
|---|---|---|
| 目次を入れる | する／しない | `book.config.js` の `entry` の `{ rel: 'contents' }` と `toc` ブロック |
| 見出し | 文字列（1〜30字。引用符・改行・バックスラッシュ不可） | `toc.title` |
| 載せる見出し | 章のタイトルのみ（0）／章＋節 `##` まで（2）／章＋節＋項 `###` まで（3） | `toc.sectionDepth` |
| 目次から外す章 | `entry` の章ごとのチェック | 判型テーマCSSの目次ブロック（§5） |
| 目次ページに書名を出す | 出す／出さない | 同上 |
| ページ番号 | 漢数字（`cjk-decimal`。例: 一二）／算用数字（`decimal`）／出さない | 同上 |
| リーダー | 点線（`leader('.')`）／三点リーダー（`leader('…')`）／なし（`leader(' ')`。番号の位置揃えのみ） | 同上 |

- **書籍単位の設定**として1区画で扱う。判型（A6・B6）ごとには分けない——テーマCSSは判型ごとにあるが、目次ブロックは同じ内容を両方に書く
- 載せる見出しの `1` は選択肢にしない（`0` と見た目がほぼ変わらず、違いを説明しにくいため）。既存の値が `1` や `4` 以上なら、その値を「その他（N）」として表示し、保存時もそのまま保つ

### 4.1 目次の有無の切り替え（`book.config.js`）

- **入れない**: `entry` から `{ rel: 'contents' }` を除き、`toc` ブロックを削除する（§2 の自動差し込みを防ぐ）
- **入れる**: `toc` ブロックを書き（なければ `entry` 配列の直後に挿入）、`{ rel: 'contents' }` がなければ挿入する。挿入位置は「**目次から外さない最初の章の直前**」（扉を外していれば扉の直後になる）。外さない章がなければ先頭。以後の位置調整は既存の「章構成（entry）」区画の上下ボタンで行う
- 状態の読み取り: `{ rel: 'contents' }` か `toc` のどちらかがあれば「入れる」とみなす（`toc` だけでも CLI は目次を作るため）
- **フェイルソフト**: `toc` がオブジェクトリテラル以外（`toc: true` 等）・入れ子の `{}` を含む・`entry` を安全に書き換えられない（`entry-sync.ts` の `canRewriteEntry` が偽）場合、`book.config.js` 側の項目は読み取り専用にして直接編集を案内する
- **書名との衝突回避**: 書誌の `title` と `toc.title` は同じキー名。書誌の抽出・置換（`extractStringValue` / `replaceStringValue`）は `toc` ブロックを除いた範囲だけを見るように直す

### 4.2 EPUB 設定への反映（`book.config.epub.js`）

- ファイルがあれば、§4.1 と同じ規則で**有無・見出し・深さ**を同じコミットに含めて書き換える
- 「目次から外す章」と見た目はEPUBに反映しない（EPUB のテーマ `theme-epub.css` は theme-base を読み込まず、ページ番号もないため。CSS で隠してもリーダーアプリのナビゲーションには残る）
- EPUB 設定が §4.1 のフェイルソフト条件に当たる場合は、印刷用だけを書き換え、保存後に「EPUB設定は書き換えられませんでした（直接編集してください）」と案内する

## 5. テーマCSSの目次ブロック

`book.config.js` と `book.config.b6.js` の `theme` が指すCSS（組み設定・ノンブルと同じ許可リスト）の末尾に、アプリが管理する1ブロックを置く。ブロックは設定から**丸ごと組み立てて書き換える**（部分置換しない）。

```css
/* ---- 目次（ネコノテAI 設定フォームが管理。begin〜end の間を手で編集するとフォームは読み取り専用になる） ---- */
/* nekonote-toc: begin */
:root {
  --vs-toc--page-counter-display: inline;
  --vs-toc--page-counter-style: cjk-decimal;
  --vs-toc--page-leader-content: leader('.') ' ';
}
h1:has(+ :is(#toc, [role='doc-toc'])) {
  display: none;
}
:is(#toc, [role='doc-toc']) li:not(:has(a)) {
  display: none;
}
:is(#toc, [role='doc-toc']) li:has(> a:is([href="manuscripts/00-tobira.html"], [href^="manuscripts/00-tobira.html#"])) {
  display: none;
}
/* nekonote-toc: end */
```

- **章の除外**は、CLI が出力するリンク先（`entry` のパスの `.md` を `.html` にし `encodeURI` したもの）で `<li>` を指定する。`sectionDepth` が1以上でリンク先に `#id` が付く場合も前方一致で拾う。`entry` の並べ替えに影響されない
- **リンクのない項目は常に隠す**（2行目のルール）。§2 の「id のない見出し」はページ番号が付かず目次として機能しないため。テンプレートの奥付（HTML直書きの `<h1>`）はこれに当たる
- **書名の非表示**は `h1:has(+ 目次nav)` で指定する（入稿ビルドの文書構造と、§7 のプレビューの構造の両方に当たる）
- **読み取り**: begin〜end の間を解析して設定を復元し、その設定から組み立て直したブロックと一致しなければ（手で編集されていれば）見た目と除外の項目を読み取り専用にする
- **ブロックがないテーマ**: 現状の見た目（書名を出す・除外なし・算用数字・点線）を初期値として表示し、保存時にブロックを末尾へ追記する（完了条件4）
- A6 と B6 のブロックが食い違っている場合は、プレビューが使うテーマ（`book.config.js` の `theme`）の値を表示し、保存で両方を揃える（区画内に注記）
- 試しビルド（2026-10-15）で、上記の `:has()` 指定・`cjk-decimal`・`leader('…')` が Vivliostyle で効くことを確認済み

## 6. 保存（1コミット）

- 書き換えるファイル: `book.config.js`・（あれば）`book.config.epub.js`・判型テーマCSS（1〜2本）。**変更があるものだけ**を Git Data API で**1コミット**にまとめる（`saveChapters` と同じ方式。#278 のコミットの分かりにくさを増やさない）
- 楽観ロック: フォームを開いた時点の各ファイルの blob SHA を送り、HEAD のツリーと1つでも違えば何もコミットせず conflict を返す
- 置換後の検証: 読み取り側と同じ解析関数で、書き込んだ設定が読めることを確かめてからコミットする（既存の設定フォームと同じ作法）
- 書き込む文字列はすべてアプリが選択肢から組み立てる。見出し文字以外にユーザー入力は入らない。除外する章のパスは、サーバー側で `entry` に実在するものに限る
- 保存前に差分（変更点の一覧）を確認させる（既存区画と同じ確認ステップ）
- コミットメッセージ: `設定: 目次を更新（ネコノテAI 縦書きエディタ）`
- コミット先は他の設定区画と同じく編集中のブランチ

## 7. 全体プレビューの目次ページ

全体プレビュー（明示操作）で、`{ rel: 'contents' }` の位置に目次ページを組み込む。章単体プレビューには出さない。

- `getAllChapterContents` が `book.config.js` から目次の情報（差し込み位置・見出し・深さ・書名）を返し、`buildPreviewHtml` が目次セクションを組み立てる
- 組み立てる構造は CLI と同じ（`<h1>書名</h1><nav id="toc" role="doc-toc"><h2>見出し</h2><ol>…`）。テーマの目次スタイルと §5 のブロックがそのまま当たる
- **ページ番号**: 各項目を同じHTML内のアンカー（`#id`）へリンクし、テーマの `target-counter()` でページ番号を出す。全体プレビューは全章を1つのHTMLに結合するため、章ごとの id の衝突（同名の見出し・脚注番号）を避けて、各章の id と章内リンクに章ごとの接頭辞を付ける
- **項目名**: 深さ0では章の見出しのテキスト（CLI の `<title>` と同じ）。ルビ記法 `{親文字|るび}` は親文字だけにする（`extractChapterTitle` を修正。章単体プレビューの柱にも効く）
- **項目**: `entry` に載っている章だけを対象にする（entry 未登録の章は全体プレビューの末尾に出るが、目次には載せない＝CLI と同じ）。§5 で外した章は項目を作らない。深さ1以上で id のない見出しは `<span>` にする（§5 のルールで隠れる＝CLI と同じ見え方）
- 目次の有無が「入れない」のときは目次ページを作らない。`toc` だけで `{ rel: 'contents' }` がない場合は先頭に置く（CLI と同じ）
- プレビューの注記「目次ページは入稿ビルドでのみ生成されます」を、「目次ページはプレビュー用に再現したもので、改ページ位置は入稿PDFと異なる場合があります」の趣旨に改める

## 8. テンプレートと既存リポジトリ

- **テンプレート**（`docs/templates/manuscript-repo/`）: `theme-bunko-a6.css`・`theme-b6.css` に目次ブロックを入れる（扉・奥付を外す・書名を出さない・漢数字・点線）。`book.config.js`・`book.config.epub.js` の `toc` に `sectionDepth: 0` を明記する
- **既存リポジトリ**: 自動配布はしない。目次区画を開いて保存すれば、足りない設定が追記される（完了条件4）。マニュアルに手順を書く

## 9. スコープ外

- 目次ページ自体の柱・ノンブルの出し分け（現在は本文と同じスロットに従う）
- 目次の項目名を章ごとに上書きする機能（項目名は章の見出しのまま）
- 縦中横でのページ番号（算用数字を縦に立てる）。必要になれば別 Issue
- EPUB の目次からの章の除外（§4.2）
