# SPEC-vertical-editor-phase5: ブランチ切替・作成・PR連携

作成日: 2026-07-23
ステータス: **確定**（2026-07-23 インタビュー2巡済み。§10 参照）
親SPEC: SPEC-vertical-editor / 起点Issue: #21
関連: SPEC-vertical-editor-phase2 §11 論点E（デフォルトブランチのみ→本Phaseで解除）

## 1. 目的

大きな改稿を安全に試したい・章の書き直しを分けて進めたい場合に、
縦書きエディタからデフォルトブランチ以外のブランチを開き、
ブランチの切替・作成、デフォルトブランチへの Pull Request 作成までを行えるようにする。

役割分担は変えない: 原稿の実体はGitHub、マージ・レビューはGitHub側、エディタは執筆とPR作成の入口まで。

## 2. スコープ（確定）

| # | 機能 | 概要 |
|---|---|---|
| 1 | ブランチ切替 | 章一覧サイドバー上部のセレクタから既存ブランチを選んで開く |
| 2 | ブランチ作成 | デフォルトブランチHEAD起点・自由命名（英数字系のみ）で新規作成→即切替 |
| 3 | PR作成 | 作業ブランチ→デフォルトブランチのPRをタイトル・本文付きで作成し、PRページURLを案内 |

### スコープ外

- 校正・講評・進捗・レビュー書き戻しのブランチ追従（**デフォルトブランチ固定のまま**。論点A）
- PRのステータス表示・マージ・レビューコメント（GitHub側で行う。論点B）
- 入稿ビルド（タグ作成）の非デフォルト対応（**デフォルトHEADのみのまま**。論点D・phase3 §8）
- 任意ブランチ起点の分岐（起点は常にデフォルトHEAD。論点C）
- ブランチの削除・リネーム（GitHub側で行う）
- DBスキーマ変更（選択ブランチはURL＋localStorage保持。論点H）

## 3. 機能仕様

### 3.1 ブランチ切替（論点E・F・H）

- **UI**: 章一覧サイドバー最上部にブランチセレクタ（DropdownMenu）。現在ブランチ名を表示し、
  開くとブランチ一覧（遅延取得）＋「新しいブランチを作成…」「Pull Request を作成…」を出す。
  集中モード中はサイドバーごと隠れる（現行どおり）
- **切替の挙動**: 確認ダイアログなしで即切替（論点F）。未保存の編集はIndexedDBへ待避される
  （キーは既に `{repo}:{branch}:{path}` でブランチ分離済み。phase2 §7）。切替時は
  章の選択状態・プレビュー・マージ状態をすべてリセットし、新ブランチの章一覧を取得し直す。
  元ブランチへ戻って章を開けば既存の復元バナーで待避を拾える
- **保持**（論点H）: 選択中ブランチは `?branch=` クエリ（history.replaceState）＋
  `localStorage`（キー `nekonote-editor-branch:{projectId}`）に保持。
  次回オープン時は `?branch=` > localStorage > デフォルトの優先で復元。
  ただし `?file=` 付き（phase4 相互リンク経由）で開いた場合は localStorage 復元を
  スキップする（リンクの意図＝デフォルトブランチ文脈の章を開くことを優先）。
  存在しないブランチ（マージ後削除等）はサーバー側でデフォルトへフォールバックし、
  トーストで通知して保存値をクリアする
- **保存ダイアログ**: コミット先ブランチ名を明示する（「デフォルトブランチにコミットします」の文言を置換）

### 3.2 ブランチ作成（論点C）

- 起点: **常にデフォルトブランチのHEAD**（Git Refs API `POST /git/refs`。Contents権限で可能——PATスコープ変更なし）
- 命名: 自由入力。検証は英数字始まり・`[0-9A-Za-z._/-]`・`..`／`//`／末尾`/`・`.lock` 拒否・100字以内
  （作成はASCIIのみ。GitHub側で作られた日本語等のブランチ名は、切替用のゆるい検証で受け入れる）
- 同名ブランチが既にある場合は conflict（日本語メッセージ）
- 作成成功後はそのブランチへ即切替する

### 3.3 PR作成（論点B）

- head=現在ブランチ・base=デフォルトブランチ固定の `POST /pulls`
- デフォルトブランチを開いているときはメニュー項目を無効化する
- タイトル初期値: `原稿: {branch} の変更`。本文は任意入力
- 差分ゼロ（422 "No commits between"）・既存PRあり（422 "A pull request already exists"）は
  日本語メッセージで案内する
- 成功時はダイアログ内にPRページへのリンクを表示する（マージはGitHub側で実施）

### 3.4 非デフォルトブランチでの各機能（論点D・G）

| 機能 | 挙動 |
|---|---|
| 本文の閲覧・編集・保存＝コミット | **現在ブランチへ**（Contents API の `ref`／`branch` 指定） |
| 新規章作成・entry自動追記 | 現在ブランチへ |
| 画像アップロード・画像プロキシ | 現在ブランチへ（プロキシは `?branch=` パラメータ追加） |
| 設定フォーム（book.config.js・テーマCSS・奥付） | 現在ブランチへ |
| 部分・全体プレビュー・テーマ解決 | 現在ブランチの内容で組む |
| 入稿ビルド（タグ作成） | **デフォルトHEADのみのまま**（ダイアログに注記） |
| 校正・講評パネル／相互リンク／書き戻し | **デフォルトブランチ対象のまま**。非デフォルト時は注記のみ（UIは隠さない。論点G） |

## 4. データ・API設計

- **DBスキーマ変更なし**。マイグレーションなし
- `lib/git/github.ts` の読み取り系（`getManuscriptTree` / `getFileContent` / `getRawFileBytes`）に
  省略可能な `ref` を、書き込み系（`putFileContent` / `createFileContent` / `createBinaryFileContent`）に
  省略可能な `branch` を追加（省略時は従来どおりデフォルトブランチ＝後方互換）
- 追加API: `listBranches`（GET /branches・最大100件）・`createBranchRef`（POST /git/refs）・
  `createPullRequest`（POST /pulls）
- Server Actions: 既存の執筆系アクションに省略可能な `branch` 引数を追加。
  追加アクション: `listEditorBranches` / `createEditorBranch` / `createEditorPullRequest`
- ブランチ名検証（zod）: 切替用（ゆるい・git禁止文字と `..` 等のみ拒否）と
  作成用（ASCII限定・§3.2）の2段。全アクションの入口で検証する

## 5. セキュリティ

- PATはserver-onlyのまま。クライアントに増える情報はブランチ名一覧とPRのURLのみ
- 新規の書き込み経路（ブランチ作成・PR作成）にレート制限を適用する
  （`editor-branch` 6/分・100/日、`editor-pr` 3/分・30/日）
- ブランチ名はAPIパス・リクエストボディに乗るため、スキーマ検証を全入口で行う（多層防御）
- **security-reviewer 必須ゲート**: GitHub書き込みAPIの追加（ブランチ・PR）と
  画像プロキシへのパラメータ追加が対象

## 7. E2E検証手順（manuscript-poc）

1. セレクタでブランチを作成 → 即切替され、URLに `?branch=` が付く
2. 章を編集して保存 → 新ブランチにコミットが存在し、デフォルトブランチは変わらない
3. リロード → 同じブランチが復元される。デフォルトへ切替→戻すと編集の待避が復元バナーに出る
4. PR作成 → GitHubにPRができ、リンクから開ける。同じブランチで再度PR作成→「既にあります」案内
5. GitHub側でPRをマージ＆ブランチ削除 → エディタを開き直すとデフォルトへフォールバック＋トースト

## 8. スコープ外（次期以降・積み残し）

- 校正・講評・進捗のブランチ追従（必要になったら SPEC-proofreading 側と合わせて別途設計）
- PRステータスのエディタ内表示・マージ操作
- 入稿ビルドの非デフォルト対応
- ブランチ間diffのアプリ内表示

## 9. 参考: 校正機能との整合（論点A・G の背景）

校正の `last_reviewed_commit`・提案の `committed_sha` はデフォルトブランチのコミットに紐づく。
非デフォルトブランチを校正対象にするには提案とブランチの対応付け設計が必要になるため、
本Phaseでは「執筆はブランチで・レビューはデフォルトで」と割り切る。
改稿ブランチをレビューしたい場合はPRマージ後にデフォルトブランチで校正する運用とする。

| # | 論点 | 決定 |
