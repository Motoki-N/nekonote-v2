# SPEC-conversational-personas: 対話型ペルソナ（ダッシュボードチャット・スケジュール提案・メモ化）

作成日: 2026-07-14（インタビュー駆動で策定）
ステータス: **確定**（2026-07-14 レビュー済み）

## 1. 目的

Sprint 5後半（R2・〜8/11）。対話型ペルソナ2人（アシスタント・喫茶店のマスター）を完成させる:

- **アシスタントのスケジュール提案**（要求仕様 §3.2「執筆スケジュール支援」: 締切・目標ページ数からペース配分を助言）
- **喫茶店のマスターの壁打ち＋メモ化**（要求仕様 §3.5: 要約＋深掘り質問、最後にメモにまとめる）
- 実装計画の「画面10: チャット（対話型ペルソナ）」に相当する会話の場

ペルソナ設計は `review-profiles` スキルが正。AI基盤（`lib/ai/models.ts`・`/api/chat`・`chat_threads`/`chat_messages`）は SPEC-ai-deep-dive で構築済みのものを拡張する。

## 2. 決定事項（インタビュー結果）

| 論点 | 決定 |
|---|---|
| 画面形態 | 独立ページは作らず**ダッシュボードに組み込み**。作業基地に相談相手が同居する形 |
| 配置・開閉 | **開閉式パネル**。ダッシュボードに「相談する」導線 → デスクトップは右サイドパネル、モバイルはボトムシート（掘り下げ・校正と同じ流儀） |
| スレッド | **ペルソナごとに1本を継続**（アシスタント／マスターの切替タブ）。「会話をリセット」で仕切り直し。スレッド一覧UIは作らない |
| メモ化・ノート保存 | メモはチャット内の応答として出し、**全AI応答に「ノートに保存」ボタン・無確認で即保存**（新規ノート作成）。マスターのメモ応答の特別扱いはしない。整理（タグ付け・改題）は後からノート側で＝手帳→浄書の思想どおり |
| スケジュール提案の入力 | **プロジェクト実データを渡す**（締切・目標ページ数・writing_progress の直近進捗）。対象は**プロジェクト1件に絞る**（アシスタントタブにプロジェクトセレクタ） |
| 掘り下げパネル | **据え置き**（アシスタント固定のまま）。マスターとの壁打ちはダッシュボード側に集約 |

## 3. 画面とUX

### 3.1 相談パネル（ダッシュボード内）

- ダッシュボードのヘッダー付近に「相談する」ボタン → パネル開閉
  - lg以上: 右サイドパネル
  - lg未満（スマホ）: ボトムシート
- パネル上部に**ペルソナ切替タブ**（アシスタント／喫茶店のマスター）。タブごとに独立した1スレッドを get-or-create し、切替時は各スレッドの履歴を表示（状態はタブ別に保持し、切替で消えない）
- メッセージ入力欄＋送信。応答は**ストリーミング表示**。送信中の多重送信抑止・stop ボタン（掘り下げパネルと同じ）
- 「会話をリセット」: スレッドごと削除（確認ダイアログあり）→ 次の送信で新スレッド
- エラーはパネル内に日本語メッセージ表示（`AppError` 経由で正規化）
- プロジェクトゼロの空状態でも開ける（アシスタントは一般的な相談相手として動く）

### 3.2 アシスタントタブ（スケジュール提案）

- タブ内に**対象プロジェクトのセレクタ**（自分のプロジェクト＋「指定なし」）
  - 既定値: 締切が最も近いプロジェクト（締切なしは後回し）。1件しかなければそれ
  - 選択は**リクエスト単位のコンテキスト**であり、スレッドとは独立（会話の途中で切り替えてもよい。切り替えた事実はAIへのコンテキスト変化として自然に伝わる）
- 選択中プロジェクトの実データを**サーバー側で**コンテキストに同梱（§5.2）。「指定なし」ならプロジェクトデータなしの雑談・ネタ出しモード
- 役割はシード済み description（整理・掘り下げ・名称のネタ出し）＋スケジュール助言。締切に対するペース配分（残日数 × 現在ペース vs 残り目標）を具体的な数字で助言できる

### 3.3 マスタータブ（壁打ち＋メモ化）

- プロジェクトセレクタなし。「その場の会話」だけで動く（reference_scope: chat_only のまま）
- 壁打ち→締めのメモ化はシード済み description が既に指示している（「会話の締めくくりには、それまでの話を短いメモにまとめて手渡す」）。ユーザーが「メモにまとめて」と頼む運用
- メモ応答が出たら「ノートに保存」（§3.4）で手帳に合流

### 3.4 ノートに保存

- **すべてのAI応答**の下に「ノートに保存」ボタン（ペルソナ・タブを問わない）
- 押したら**無確認で即、新規ノートを作成**:
  - `title` = 応答本文の1行目（Markdown記号 `#` `-` `*` `>` 等を除去、最大50字）
  - `content` = 応答本文そのまま（Markdown）
  - タグなし（後からノート側で仮タイトルタグ等を付けて整理する）
- 保存成功後はボタンを「保存済み」表示に変えて再押下を抑止（誤操作の重複ノートを防ぐ）＋作成ノートへのリンクを表示
- 保存の実体は messageId を渡す Server Action（本文はDBから読み直す＝クライアント改変の混入を防ぐ）。ストリーミング直後でまだDB保存が完了していない応答はボタンを無効にしておく（onFinish 後に有効化）

## 4. データ

### 4.1 マイグレーション（1本のみ・プランモード承認）

新テーブル・シード変更なし。**部分ユニークインデックスを1本追加**するだけ:

```sql
-- ダッシュボード相談はペルソナごとに1スレッド（note_id null 行）。
-- get-or-create の同時実行を 23505 で捕捉できるようにする（note スレッドと同じ流儀）
create unique index chat_threads_user_persona_dashboard_uniq
  on public.chat_threads (user_id, persona_id)
  where note_id is null;
```

- 既存の note スレッド（note_id 非null）には影響しない
- 将来スレッド一覧型に拡張する場合はこのインデックスを外す（それまでの「1本継続」をDBレベルで保証）

### 4.2 reference_scope の解釈（マイグレーション不要の設計判断）

- アシスタントの `reference_scope: 'chat_only'` は**変更しない**。要求仕様 §3.5 の定義（「プロット等の資料把握は不要・チャット文脈のみ」）における「資料」は原稿・企画・ノートを指す
- スケジュールデータ（projects の締切・目標ページ数・writing_progress）は資料ではなく**進捗メタデータ**であり、アシスタントの役割（スケジュール・進捗管理）の入力としてコードが同梱する。要求仕様 §3.5 自体がこの役割と chat_only を併記しており、整合する
- マスターは chat_only をそのまま適用（何も同梱しない）

## 5. 実装方式

### 5.1 Server Actions（`lib/actions/chat.ts` に追加）

- `getOrCreateDashboardThread(personaId)`: note_id null＋persona_id でget-or-create。23505 は取り直し（既存の note スレッドと同じレースハンドリング）。personaId は**サーバー側で conversational 型かを再検証**（reviewer 型のスレッドを作らせない。標準 or 自分のペルソナ所有チェックはRLSが担う）
- `saveChatMessageAsNote(messageId)`: chat_messages を RLS 越しに取得（親スレッド経由の所有確認）→ role='assistant' 検証 → notes に insert → 作成ノートidを返す
- リセットは既存 `resetDeepDiveThread` を共用（実体は「スレッド削除」で同じ。名前は `resetThread` に一般化してよい）

### 5.2 `/api/chat` の拡張

リクエストを判別可能な2形態に:

```
{ threadId, messages, context: { kind: 'note', note: {...} } }        … 既存（掘り下げ）
{ threadId, messages, context: { kind: 'dashboard', projectId? } }    … 今回追加
```

- サーバー側でスレッドの実態と照合: note_id 非null のスレッドに dashboard コンテキスト（またはその逆）が来たら validation エラー
- dashboard 分岐:
  1. thread の RLS 取得（所有確認・担当ペルソナ）は既存どおり
  2. `projectId` があれば **RLS 越しに projects を取得**（他人のプロジェクトidは not_found＝IDOR遮断）＋ writing_progress の直近30日
  3. スケジュールコンテキストを**サーバーで組み立て**（クライアントからの自由文コンテキスト注入はさせない）: プロジェクト名・ステータス・イベント名・締切と**残日数（JST計算）**・目標ページ数・最新総文字数・直近7日/30日の増分と1日あたりペース
  4. ペルソナがマスター（＝chat_only を厳密適用したい相手）のときは projectId を無視してよい（実装はペルソナの reference_scope でなく「アシスタント以外は同梱しない」で単純に）
- system プロンプト: `lib/ai/prompts.ts` に `buildDashboardChatPrompt({ personaDescription, schedule? })` を追加。ペルソナ description＋共通の役割指示（日本語・簡潔・モバイルで読める分量）＋schedule ブロック（あれば）
- 履歴は**直近20メッセージ**制限・onEnd での差分保存・保存失敗で応答を壊さない、はすべて既存実装を共用

### 5.3 UI コンポーネント

- `components/dashboard/consult-panel.tsx`（仮）: パネル本体（タブ・スレッド状態・useChat）。ペルソナごとの useChat インスタンスを保持し、per-request `body` で context を送る（掘り下げパネルの流儀）
- ダッシュボード（`app/page.tsx`）はサーバーコンポーネントのまま、パネルのトリガーと初期データ（conversational ペルソナ2人・プロジェクト一覧の最小情報）を渡す。**トリガーのJSXはクライアント側で組み立てる**（セッション⑫の hydration 教訓）
- 色はテーマ用CSS変数のみ

## 7. スコープ外

- スレッド一覧・複数スレッド・履歴検索（テーブルは対応済み。必要になったらインデックス差し替えで拡張）
- 構造化スケジュールの保存・ダッシュボード表示（提案はチャット内で完結）
- 掘り下げパネルのペルソナ切替（アシスタント固定のまま）
- メモ化の自動ノート作成（保存は常にユーザーのボタン操作）
- 保存時のタイトル・タグ指定ダイアログ（後からノート側で整理）
- 会話履歴の要約・トークン最適化・使用量計測
- キャラクターレビューの実行UI（プロファイル …1002。別途検討のまま）

## 8. E2E検証手順（完了条件）

1. **パネル開閉**: ダッシュボードから相談パネルを開閉できる（デスクトップ=サイド、スマホ幅=ボトムシート）
2. **ペルソナ切替**: アシスタント／マスターのタブ切替でそれぞれ別スレッド・別の口調。切替しても双方の表示状態が保持される
3. **履歴永続化**: リロード後も各タブの会話が復元される（DBで note_id null・persona_id 別の2スレッドを確認）
4. **スケジュール提案**: プロジェクトを選んで「ペース配分を相談」→ 締切・残日数・直近の実文字数を踏まえた具体的助言が返る（実データの数字が応答に現れる）
5. **プロジェクト切替**: セレクタで別プロジェクト（または指定なし）に切り替えると、以降の応答のコンテキストが変わる
6. **マスターの壁打ち→メモ化**: 漠然とした構想を話す→要約＋深掘り質問が返る→「メモにまとめて」で短いメモ応答
7. **ノートに保存**: メモ応答を保存→ /notes に新規ノートが現れる（title=1行目・content=全文）。ボタンが「保存済み」になり再押下できない。リンクからノートが開く
8. **会話リセット**: 確認ダイアログ→履歴全消去→新しい会話を開始できる（もう一方のタブは無傷）
9. **レース**: 同一ペルソナのスレッド二重作成が部分ユニークで防がれる（get-or-create の取り直し動作）
10. **RLS/認証**: 未認証で /api/chat・Server Actions が弾かれる。他人の projectId を渡しても not_found（IDOR遮断）
11. **モバイル375px**: 2〜8 の全操作がボトムシートで成立する
12. **既存回帰**: ノート掘り下げパネル（note スレッド）が従来どおり動く

※ マイグレーションと `/api/chat` 拡張（projectId の所有確認・コンテキスト組み立て）・`saveChatMessageAsNote` は **security-reviewer 必須ゲート**の対象。
