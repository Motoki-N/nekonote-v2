# SPEC-review-history: レビュー履歴一覧・閲覧画面

作成日: 2026-07-27（Issue #59・インタビュー駆動で策定）
ステータス: **確定**（2026-07-27 インタビュー済み）

## 1. 目的

Issue #59 の残スコープを実装する。レビューセッションの履歴データは
`review_sessions` / `review_feedbacks` に残っているが、セッションが completed になる
（「企画を通す」等）とUIから閲覧できなくなる。過去セッションを一覧・閲覧できる画面を追加する。

なお Issue #59 のもう一方の要求「複数並行実行」は、SPEC-dashboard-critique-settings §3.2
（対象×プロファイルごとの running セッション並存＋セレクタ切替）で実装済みのため対象外。

## 2. 決定事項（インタビュー結果）

| 論点 | 決定 |
|---|---|
| 置き場所 | **プロジェクト配下の新タブ** `/projects/[id]/reviews`（企画書｜構成ボード｜原稿｜エディタに「レビュー履歴」を追加） |
| 対象範囲 | **全フェーズ統合**: 企画書・構成・シーン・キャラクター・講評（manuscript）をすべて1つの一覧に出す。既存の講評パネル内履歴はそのまま残す |
| 操作範囲 | **閲覧＋クリップボードコピー**。フィードバック本文をコピーできる。削除・再開・返答メモ編集はしない（読み取り専用） |
| ステータス | running / completed / failed を**問わず全件**表示（running の続きは従来どおり各対象画面のパネルで行う） |

## 3. 画面とUX

### 3.1 タブ追加（components/projects/project-tabs.tsx）

- 既存タブ列の末尾に「**レビュー履歴**」（`/projects/[id]/reviews`）を追加

### 3.2 /projects/[id]/reviews レビュー履歴ページ（新設）

- プロジェクトの全レビューセッションを**作成日時の降順**で一覧表示
- 行（アコーディオン summary）の表示:
  - **フェーズバッジ**: 企画書 / 構成 / シーン / キャラクター / 講評（review_profiles.target_phase から導出。プロファイル削除済みで導出不能なら「レビュー」）
  - **プロファイル名**（削除済みは「（削除済みプロファイル）」）・**ペルソナ名**（削除済みは非表示）
  - **対象ラベル**: シーンレビューはシーン名（削除済みは「（削除済みシーン）」）、ノート絞り込みキャラクターレビューはノート名。企画書・構成・講評は対象が自明のため出さない
  - **ステータスバッジ**: 実施中（running）/ 完了（completed）/ 失敗（failed）
  - **フィードバック回数**・**最新判定**（承認/差し戻し。verdict がある場合のみ）・**作成日時**
- 行を開くと**その時点でフィードバックを遅延取得**し、レビュー往復を読み取り専用で表示:
  - 第N回・判定バッジ（verdict 非null のみ）・日時・フィードバック本文
  - 返答メモ（user_response 非null のみ。読み取り専用表示）
  - **コピー**ボタン: フィードバック本文を `navigator.clipboard` でコピーし toast 通知
- 空状態: 「まだレビュー履歴がありません」
- 検索・絞り込み・ページネーションは付けない（一人利用・1プロジェクトの件数規模。§6）
- 色はテーマ用CSS変数のみ。モバイル（375px）で崩れないこと

## 4. データ

**スキーマ変更なし**。既存の `review_sessions` / `review_feedbacks` を RLS 越しに読むだけ。

- 一覧: `review_sessions`（project_id 絞り込み）＋ `review_profiles(name, target_phase)` /
  `personas(name)` / `review_feedbacks(verdict, created_at)`（回数と最新判定の導出用）を join
- 対象ラベル解決: scene フェーズは `scenes` を、note_id 付きは `notes` をまとめて引いてタイトルを付与
- フィードバック本文は行を開いたときに `review_feedbacks` から遅延取得（一覧を軽く保つ）

## 5. 実装方式

| ファイル | 役割 |
|---|---|
| `lib/actions/review-history.ts` | `listReviewSessions(projectId)`（一覧サマリ組み立て）・`getReviewHistoryFeedbacks(sessionId)`（遅延取得。RLS越し＝所有確認） |
| `app/(app)/projects/[id]/reviews/page.tsx` | サーバーコンポーネント。一覧を取得して ReviewHistoryList に渡す |
| `components/reviews/review-history-list.tsx` | クライアント。アコーディオン一覧・遅延取得・コピー |
| `components/projects/project-tabs.tsx` | 「レビュー履歴」タブ追加 |

## 6. スコープ外

- completed セッションの再開・削除・返答メモの編集（閲覧専用）
- フェーズ・プロファイルでの絞り込み、検索、ページネーション
- プロジェクト横断の履歴一覧（プロジェクト単位で足りる）
- 講評パネル内の既存履歴一覧の変更（重複掲載は許容。パネルは実行の場、本画面は振り返りの場）

## 7. E2E検証手順（完了条件）

1. **タブ表示**: プロジェクト配下に「レビュー履歴」タブが出て、クリックで一覧が開く
2. **一覧表示**: 全フェーズのセッションが作成日時降順で並び、フェーズ・プロファイル名・ペルソナ名・ステータス・回数・日時が表示される
3. **閲覧**: 行を開くとフィードバック往復（本文・判定・返答メモ）が読み取り専用で表示される
4. **コピー**: コピーボタンでフィードバック本文がクリップボードに入り toast が出る
5. **completed の閲覧**: 「企画を通す」で completed になったセッションの履歴が読める（Issue #59 の主目的）
6. **削除済み参照**: プロファイル・ペルソナ・シーンを削除した履歴でも一覧が壊れない
7. **RLS/認証**: 未認証はログインへ。他人のプロジェクトid・sessionId では not_found / 空
8. **モバイル375px**: 一覧・展開・コピーが成立する
