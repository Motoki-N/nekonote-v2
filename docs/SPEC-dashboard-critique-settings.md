## 1. 目的

- **ダッシュボード**: プレースホルダーのトップページを「作業基地」に置き換える。執筆進捗の可視化と進行中プロジェクトの概況・導線を提供する（要求仕様 §3.6 の起点）
- **プロファイル選択UI**: レビュー実行時のプロファイル固定（コード直付け）をやめ、「プロファイル＋担当ペルソナ＋対象」の組で実行する本来の設計（要求仕様 §3.5）に到達する
- **講評系**: 読者代表・近所の書店員による「作品全体への講評」を実装し、レビュー型ペルソナ6人全員に起用経路を通す
- **設定画面拡張**: ペルソナ・レビュープロファイルの管理（複製・編集・新規・削除）とAIモデルマッピング編集を `/settings` に載せ、要求仕様 §4.4「設定変更のみでモデル追従」を画面から行えるようにする

## 2. 決定事項(インタビュー結果・2巡)

1巡目(方針):

| 論点 | 決定 |
|---|---|
| スコープ | 対話型ペルソナは**別SPEC**に分離。今回は4項目に絞る |
| ダッシュボードの中心 | **進捗＋プロジェクト概況**の「作業基地」型（進捗グラフとプロジェクト概況カードの両方） |
| 講評の対象・場所 | **原稿タブから、base_path配下の全原稿ファイルを構成順に結合して「作品全体」への講評**（要求仕様「書き上がった原稿を評価」に忠実） |
| 設定画面の範囲 | **フル編集**: プロファイルCRUD＋ペルソナ編集＋AIモデルマッピング（要求仕様に完全準拠） |

2巡目(派生する落とし穴):

| 論点 | 決定 |
|---|---|
| プロファイル切替と履歴 | **プロファイルごとにセッション並存**。対象×プロファイルの組ごとに継続セッションを持ち、切り替えるとそのプロファイルの過去履歴に戻れる（現行の profile_id 絞り込み検索の自然な一般化） |
| 担当ペルソナ変更 | **セッション開始時のみ**。新規セッション開始時に選択（既定はプロファイルの default_persona）。進行中セッションの途中変更は不可＝会話の一貫性とデータモデル（persona_id 1人記録）が素直 |
| 講評のセッション型 | **読み切り型**。講評は毎回独立実行し、履歴一覧として残す（反復・返答メモなし）。「一読者の体験」のシミュレーションとして自然 |
| 進捗データの鮮度 | **手動更新ボタン**。ダッシュボードは記録済み writing_progress を表示し、「今すぐ集計」ボタンでGitHub集計を明示的に実行できる（repo/PAT設定済みプロジェクトのみ） |

インタビューで聞かずに設計原則で決めた点(レビューで確認済み):

- **マイグレーション1本**: `review_profiles.target_phase` のCHECK制約に `'manuscript'` を追加＋講評プロファイル2種をシード（「読者講評」= 読者代表、「書店員講評」= 近所の書店員。固定UUID `…1006` / `…1007`）。スキーマの新テーブル・新列はなし
- **講評も review_sessions / review_feedbacks に保存**する（新テーブルを作らない）。読み切り型=1実行1セッションで、完了時に `status: 'completed'` で確定。verdict は null（講評に合否はない）。`target_ref` はプロジェクトid（作品全体への講評のため）
- **講評の入力はペルソナの reference_scope で出し分け**る: `manuscript_only`（書店員）= 原稿のみ / `manuscript_plus_target`（読者代表）= 原稿＋企画書のジャンル・ターゲット層のみ / `all`（担当編集を起用した場合）= 原稿＋企画書全文。reference_scope をコードが解釈する初のケースだが、既存の「kind別入力構築」の分岐に載る
- **読者代表の講評は、企画書のジャンル・ターゲット層が未設定なら実行不可**＋企画書タブへの誘導を表示（なりきり先がないと意味を成さないため。フェイルクローズ）
- **全文結合は原稿ツリーの表示順（パス辞書順）**で、ファイル名を見出し（`## ファイル名`）として挿入。文字数ガードは二段構え: **15万字超は実行前に確認メッセージ**（長編小説の上限相当を超えている旨と概算文字数を示し、ユーザーが了承すれば実行）、**30万字超は AppError の日本語エラー**で実行不可（現行作品は約3.7万字で十分な余裕）
- **標準同梱のペルソナ・プロファイルは読み取り専用＋「複製して編集」**。スキーマのCHECK制約（`is_default and user_id is null`）とRLSが既にこれを強制しており、UIもそれに従う。複製はユーザー行としてコピーを作る
- **ユーザー作成プロファイルの削除は確認ダイアログ経由の物理削除**。review_sessions は `on delete set null` で履歴が残る（スキーマ設計どおり）。ペルソナ削除も同様（ただしプロファイルの default_persona_id が null になる場合は選択UIで既定なし扱い）
- **レビュー・講評に起用できるペルソナは `persona_type: 'reviewer'` のみ**（conversational は対話型SPECの領分）。ペルソナ編集UIでは persona_type も選べるが、reviewer 以外はレビュー起用の選択肢に出さない
- **`PROFILE_BY_KIND` の固定ID直付けを廃止**し、target_phase によるDB検索（標準＋自分のプロファイル）に一般化する。既定選択は標準プロファイル（is_default）。対象を開いたときに running セッションが最新のプロファイルがあればそれを初期表示
- **AIモデルマッピングUI**は capability 3行（high/medium/low）× provider セレクト＋model_id 自由入力。ユーザー行がなければ `DEFAULT_MODEL_MAP` の値をプレースホルダー表示し、「デフォルトに戻す」=行削除。プロバイダAPIキーの環境変数が未設定の場合はサーバーで判定して警告バッジを出す（キー値は一切クライアントへ渡さない）
- **ダッシュボードのグラフはSVG折れ線の自作**（ビートボードの感情折れ線で実績あり。チャートライブラリは追加しない）。target_pages→文字数の目標線は換算係数が未定義のため今回見送り（スコープ外に記載）
- **進捗の手動更新は既存の集計ロジック（openManuscriptFile 内の全ファイル集計）を関数として切り出して再利用**。10並列制限・JST日付・フェイルソフトの挙動はそのまま

## 3. 画面とUX

### 3.1 ダッシュボード（`/` 置き換え）

- ヘッダーは現行を維持（設定・テーマ・ログアウト）
- **プロジェクト概況カード**（アーカイブ以外のプロジェクトを更新日降順）:
  - プロジェクト名・イベント名・企画書ステータスバッジ（draft/in_review/approved）
  - 締切カウントダウン（「あと n 日」。締切超過は destructive 表示、未設定は非表示）
  - 最新の総文字数（writing_progress の最新行）＋最終記録日
  - **直近30日の文字数推移のSVG折れ線**（記録が2点未満なら「記録がたまると推移が表示されます」）
  - 「今すぐ集計」ボタン（repo/base_path・PAT設定済みのプロジェクトのみ表示。実行中スピナー→完了でグラフ・数値更新。失敗は日本語トースト）
  - カードから企画書・ビートボード・原稿タブへの導線
- プロジェクトゼロの空状態: プロジェクト作成とノートへの導線
- ノート導線（「ノートをひらく」）は維持

### 3.2 プロファイル選択UI（レビューパネル拡張）

- `review-panel` ヘッダーに**プロファイルセレクタ**を追加: 対象の target_phase に合う「標準＋自分のプロファイル」を列挙。既定は running セッションが最新のプロファイル、なければ標準
- 切り替えると**そのプロファイルのセッション状態に切り替わる**（対象×プロファイルごとに running 高々1本。並存）
- **新規セッション開始時のみ担当ペルソナを選択**できる（既定はプロファイルの default_persona。reviewer のみ列挙）。既存セッションではペルソナ名を固定表示
- 適用範囲: 企画書レビュー・構成レビュー・シーンレビュー（既存3経路すべて）。校正（proofreading）はワークフローが別物（revision_suggestions）のため対象外

### 3.3 講評（原稿タブ）

- 原稿タブのヘッダーに**「講評」ボタン**を新設（ファイルを開いていなくても押せる。原稿ファイルが1件もなければ無効）
- パネル（デスクトップ=サイドパネル、モバイル=ボトムシートの既存パターン）:
  - プロファイル（manuscript phase: 読者講評・書店員講評＋自分の複製）とペルソナ（既定=default_persona）を選んで「講評を受ける」
  - 読者講評でジャンル・ターゲット層未設定なら実行ボタン無効＋企画書タブへの誘導文
  - 原稿全体が15万字を超える場合は実行前に確認ダイアログ（概算文字数を提示。了承で実行）。30万字超は実行不可の日本語エラー
  - 実行中はストリーミング表示（既存レビューと同じ逐次描画・stop可）。完了時に保存
  - **履歴一覧**: 過去の講評を新しい順に（日時・プロファイル名・ペルソナ名・本文は折りたたみ）。返答メモ・再レビューボタンは置かない（読み切り型）

### 3.4 設定画面拡張（`/settings`）

セクション構成（上から）:

1. **AIモデル設定**: capability 3行のテーブル（担当ペルソナ名を添える）。provider セレクト＋model_id 入力＋保存、「デフォルトに戻す」。APIキー未設定プロバイダに警告バッジ
2. **ペルソナ**: 標準6人＋ユーザー作成の一覧（名前・型・能力・参照範囲）。標準は閲覧＋「複製」のみ、ユーザー行は編集・削除。編集項目: name / description（textarea）/ ai_capability / reference_scope / persona_type
3. **レビュープロファイル**: 標準5種＋講評2種＋ユーザー作成の一覧（名前・対象フェーズ・担当）。標準は閲覧＋「複製」のみ、ユーザー行は編集・削除。編集項目: name / target_phase / prompt_template（textarea）/ default_persona_id（reviewer のみ列挙）
4. **GitHub連携**: 既存のまま

- 編集はダイアログ（モバイルはボトムシート）。削除は確認ダイアログ（履歴は残る旨を明記）
- prompt_template / description は補間変数を持たない素のプロンプト本文（現行実装どおり）で、プレビュー機能は付けない

## 4. データ

マイグレーション `20260714000001_manuscript_critique_profiles.sql`:

- `review_profiles.target_phase` のCHECK制約を張り替えて `'manuscript'` を追加
- 講評プロファイル2種をシード（is_default・user_id null）:
  - 読者講評（`e5a1c0de-1006-…`）: default_persona = 読者代表。ターゲット層になりきった主観的感想（刺さった・飽きた・続きが気になる等）を、体験した順に返すプロンプト
  - 書店員講評（`e5a1c0de-1007-…`）: default_persona = 近所の書店員。売れそうか・小説として優れているか・どの層に受けそうかの客観評価（辛辣可）を返すプロンプト

既存テーブルの使い方の一般化（スキーマ変更なし）:

- `review_sessions`: 検索キーを（target_ref × review_profile_id × status='running'）に統一（現行実装の固定IDを引数化するだけ）。講評は target_ref=プロジェクトid・1実行1セッション（作成→ストリーム→onFinish で completed。失敗時は failed）
- `personas` / `review_profiles`: ユーザー行のCRUDを追加（RLSは既存定義のまま）
- `ai_model_settings`: upsert（user_id×capability一意）と削除を追加
- `writing_progress`: 変更なし（手動更新は既存 upsert の再利用）

## 5. 実装方式

- `/api/review` を拡張: kind に `'manuscript'` を追加し、リクエストで `profileId` / `personaId` を受ける（**サーバー側で所有確認**: プロファイル・ペルソナとも「標準 or 自分の行」をRLS越しに再検証し、phase と kind の対応・persona_type='reviewer' も検証する。クライアント指定値を信頼しない）
- 講評の入力構築はサーバー側: PAT復号→GitHubツリー取得→base_path配下の原稿ファイルを辞書順に全取得（10並列制限を流用）→見出し付き結合→文字数ガード（30万字超はエラー。15万字超の確認はクライアント側で事前に総文字数を出して行い、確認済みフラグをリクエストに載せる）→reference_scope で企画書情報を付加
- `lib/actions/review.ts`: `getOrCreateReviewSession(kind, targetId, profileId, personaId?)` に一般化。`PROFILE_BY_KIND` 削除。講評用に `listCritiqueSessions` / `createCritiqueSession` を追加
- `lib/actions/settings.ts`: ペルソナ・プロファイルの複製/作成/更新/削除、ai_model_settings の upsert/削除、プロバイダキー有無の判定（boolean のみ返す）を追加
- ダッシュボードはサーバーコンポーネントで一括取得（projects＋最新 writing_progress＋直近30日）。手動集計は Server Action（進捗集計関数を `lib/actions/manuscripts.ts` から切り出して共用）
- **security-reviewer 必須ゲート**: マイグレーション（CHECK制約張り替え＋シード）と実装（/api/review の profileId/personaId 受け入れ＝IDOR注意・設定CRUDのRLS/所有確認・PAT復号経路の拡張・キー有無判定の情報非漏洩）
- 検証: `npm run typecheck` / `npm run lint` / §8 のE2E

## 8. E2E検証手順（完了条件）

1. **ダッシュボード**: プロジェクト概況カードに締切カウントダウン・企画ステータス・最新文字数・折れ線が出る。プロジェクトゼロの空状態も確認
2. **手動集計**: 「今すぐ集計」→ writing_progress 当日行が upsert され、グラフ・数値が更新される（DB直接確認）。repo未設定プロジェクトにはボタンが出ない
3. **プロファイル複製・編集**: 標準「企画書レビュー」を複製→プロンプト編集→企画書レビューでそのプロファイルを選択して実行→フィードバックに編集内容が反映される
4. **セッション並存**: 標準プロファイルの既存セッションと複製プロファイルのセッションが対象ごとに並存し、セレクタ切り替えで各履歴に戻れる（DB で review_profile_id 別 running 2本を確認）
5. **ペルソナ選択**: 新規セッション開始時にペルソナを default 以外へ変更→ review_sessions.persona_id に記録。進行中セッションでは変更UIが出ない
6. **書店員講評**: 原稿タブ→講評→書店員講評で実行→全ファイルを踏まえた講評がストリーミング表示→履歴に残る（verdict null・completed をDB確認）
7. **読者講評**: ジャンル・ターゲット層未設定で実行不可＋誘導表示→企画書に設定→実行可。講評にターゲット層の視点が反映される
8. **講評の読み切り**: 2回実行すると履歴が2件並ぶ（反復・返答UIがない）
