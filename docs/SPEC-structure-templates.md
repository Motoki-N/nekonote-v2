# SPEC-structure-templates: 構成テンプレート（ビートボードの複数手法対応）

作成日: 2026-07-31（Issue #54。設計インタビュー駆動で策定）
ステータス: 確定（2026-07-31 プラン承認済み）

## 1. 目的

ビートボード（SPEC-beat-board）の構成手法を、現行のラリー・ブルックス流4部構成固定から、プロジェクトごとに選べる6テンプレート制に拡張する。レーン構成・転換点の定義は Issue #54 コメント（2026-07-31 版）が正。

対象は小説プロジェクト（ビートボード）のみ。目次ボード（SPEC-outline-board。技術書・その他）はテンプレート機能の対象外で無変更。

## 2. 決定事項（インタビュー結果）

| 論点 | 決定 |
|---|---|
| スコープ | 5テンプレート一括追加（既存4部構成と合わせて6種） |
| データモデル | テンプレート定義はコード内の宣言的定数（`lib/board-templates.ts`）。DBは `projects.structure_template` カラム＋ part / anchor の CHECK 語彙拡張のみ（draft-to-clean-model 準拠。テンプレート用テーブルは作らない） |
| 転換点の並び順固定 | **ドロップ時バリデーション**。レーン内の転換点付きシーンの相対順がテンプレ定義に違反するドロップはロールバック＋トーストで拒否。サーバー（Server Actions）でも同一の純関数で検証 |
| テンプレート切替 | いつでも可。**確認ダイアログ→全シーンを新テンプレの先頭レーンへ集約・転換点マーク全解除**。タイトル・本文・感情・ノート紐づけ・シーン承認状態は保全。構成承認（`projects.structure_status`）は draft に戻す |
| 選択UI | ボードヘッダーのセレクト |
| 現行4部構成 | 既定テンプレートとして無変更で共存（既存プロジェクトは無影響）。ストラクチャー式は6番目の別テンプレート |
| AIレビュー | 構成レビュープロファイルは1本のまま。user 入力に「採用中の構成テンプレート」節（レーン構成・転換点チェックリスト）を動的注入 |

## 3. テンプレート定義

スラッグはテンプレート横断で一意（新テンプレはプレフィックス付き）。これによりグローバル対応表（`PART_LABEL` / `ANCHOR_LABEL` / `ANCHOR_TO_PART` / `BOUNDARY_ANCHOR_BY_PART`）が template 引数なしで成立し、`toCanonicalOrder` は無変更で全テンプレに適用できる。

**【ア】= アンカー（境界転換点）**。該当レーンの末尾スロットに固定表示され、ドラッグ並び替え不可（現行の PP1/ミッドポイント/PP2 と同じ挙動）。その他の転換点はバッジ表示でレーン内を動かせるが、転換点同士の相対順はテンプレ定義順に制約される（§5）。

## 4. データ

マイグレーション `20260731000001_structure_templates.sql`:

1. `projects.structure_template text not null default 'four_part'`＋CHECK（6テンプレID）。既存行は default で4部構成
2. `scenes_part_check` を drop→add で全テンプレのレーン語彙＋`chapter` に拡張（20260725000004 の前例踏襲）
3. `scenes_anchor_check` を同様に全転換点語彙へ拡張
4. 標準シード「構成レビュー」の `prompt_template` 更新: 4部構成固定のチェックリスト節を「user 入力の『採用中の構成テンプレート』節に従う」旨へ差し替え（判定行の書式は一字一句維持。技術書構成レビューは無変更）

RLS 変更なし。運用セマンティクス:

- `scenes.part` は「`chapter`」または「プロジェクトの現テンプレートのレーン」のみ有効。Server Actions で検証する（DB CHECK は全テンプレの和集合のため、テンプレ整合はアプリロジックの担保）
- `scenes.anchor` の part 整合は従来どおり `ANCHOR_TO_PART`（グローバル対応表）で正規化
- 1転換点1シーン・境界アンカーのレーン末尾固定は従来ロジックを全テンプレに適用
- テンプレート切替は「scenes 一括更新 → projects 更新」の2文（supabase-js にトランザクションがないため。scenes 側を先に更新し、途中失敗時は再実行で自己修復する順序）

## 5. 転換点の並び順制約

- レーン内で転換点付きシーンの相対順は、テンプレ定義の転換点順（§3 の「/」区切り順）に一致しなければならない。転換点なしの自由シーンは転換点の間にも自由に置ける
- 検証は共用純関数 `findTurningPointOrderViolation(scenes, template)`（`lib/board.ts`）:
  - クライアント: ドロップ確定時に違反を検出したらロールバック＋トースト
  - サーバー: `updateScene` / `reorderScenes` で違反を `AppError('validation')` にする（ダイアログでのアンカー付与が順序違反になる場合も同様に拒否）
- 境界アンカーは正準順序（`toCanonicalOrder`）がレーン末尾に固定する（従来どおり）

## 6. 画面とUX

- **テンプレセレクト**: ボードヘッダー（「構成レビューを受ける」の並び）に現テンプレ名のセレクトを表示。変更を選ぶと確認ダイアログ:
  - 文言に「全シーンは『（新テンプレ名）』の先頭レーンに移動し、転換点マークはすべて解除されます。構成の承認状態もリセットされます。シーンの内容・感情・ノート紐づけは保持されます」を明示
  - 確定で `switchStructureTemplate` を実行し、ボードを新テンプレのレーンで再描画
- **レーン描画**: 現テンプレの `lanes` 定義順。レーンヘッダーはテンプレ定義の label＋短い説明
- **アンカースロット**: 境界転換点を持つレーンの末尾に固定スロット（未設定時プレースホルダー含め従来どおり）
- **転換点バッジ**: 非境界転換点はバッジ付き通常カード（従来のピンチポイントと同じ操作感＋順序制約）
- **編集ダイアログ**: パート選択肢=現テンプレのレーン、アンカー選択肢=選択中レーンの転換点（テンプレ定義順）
- 目次ボード・感情折れ線・ノート紐づけ・ゲート（通す）機能は無変更

## 7. AIレビュー

- 構成レビューの user 入力に「採用中の構成テンプレート」節を注入: テンプレ名＋レーン構成と転換点一覧（定義から自動生成）＋テンプレ固有のレビュー観点（`reviewChecklist`。4部構成は現行シードのチェックリスト文言を移植、新5種は各手法の定石で起草）
- 構成見出しは `# 構成（○○・構成順）`（○○=テンプレ名）
- シーンレビューの user 入力にもテンプレ名を1行追加（パート・アンカーのラベルはグローバル対応表で自動追従）
- 判定行の書式・parseVerdict・レビュー入力の文字数ガードは無変更

## 8. スコープ外

- テンプレートのユーザー定義（カスタムテンプレート）
- テンプレ切替時の転換点自動マッピング（旧→新の対応表）
- story-engineering スキル自体の多テンプレ化（4部構成の基盤知識のまま。レビュー観点は本機能のレジストリ側で持つ）

## 9. E2E検証手順（完了条件)

1. **回帰**: 既存（4部構成）プロジェクトのボードが従来どおり表示・D&D・編集・レビューできる
2. **切替**: セレクトで三幕構成を選択→確認ダイアログ→全シーンが第一幕へ集約・アンカー解除・構成承認リセット。タイトル・本文・感情・ノート紐づけが保持されている
3. **各テンプレ描画**: 6テンプレでレーン・境界アンカースロット（未設定プレースホルダー含む）・転換点バッジが §3 の定義どおり
4. **順序制約**: 転換点付きシーン2枚を定義順と逆になるようドロップ→ロールバック＋日本語トースト。編集ダイアログで順序違反になるアンカー付与→エラー
5. **1転換点1シーン**: 新テンプレの転換点でも付け替えで元シーンから外れる
6. **構成レビュー**: 三幕構成のプロジェクトでレビュー実行→入力にテンプレ節が含まれ、指摘が三幕の観点になる。判定バッジ・「構成を通す」が従来どおり動く
7. **目次ボード回帰**: 技術書プロジェクトの目次ボードが無変更で動く（セレクト非表示）
